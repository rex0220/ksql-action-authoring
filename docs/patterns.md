# 集計と明細の標準形

関連レコードを集計して別アプリに反映する、いちばん多い形。
**消してから入れ直すのではなく、「今の集計を 0 の行として `UNION ALL` で足してから集計し、`UPSERT` で書く」**（仕様 §6.2）。
迷ったらこの形から始めてください。

**文は役割ごとに分けます**（1 集める / 2 集計 / 3 書き込む）。1 文にまとめても結果・API・所要は変わりませんが、
分けたほうが読みやすく、**実行計画（`kact_explain`）が 1 文ずつ対応します**。

```sql
-- @ksql dialect: 1
DECLARE @cust = '';

-- 1. 集める。受注の 1 行を「件数 1」として並べ、今の集計を「0 の行」として足す
CREATE TEMP TABLE #raw AS
SELECT 顧客コード, 1 AS 件数, 金額 AS 売上
  FROM LAPP_受注 WHERE 顧客コード = @cust
UNION ALL
SELECT 顧客コード, 0 AS 件数, 0 AS 売上
  FROM LAPP_集計 WHERE 顧客コード = @cust;

-- 2. 集計する（手元の計算。kintone には行かない）
CREATE TEMP TABLE #agg AS
SELECT 顧客コード, SUM(件数) AS 件数, SUM(売上) AS 売上
  FROM #raw GROUP BY 顧客コード;

-- 3. 書き込む。受注が 0 件になったキーは「0 の行」だけが残るので 0 で更新される
UPSERT INTO LAPP_集計 (顧客コード, 件数, 売上, 集計日時)
SELECT 顧客コード, 件数, 売上, @NOW() AS 集計日時
  FROM #agg
ON DUPLICATE (顧客コード);
```

設定側は、`params` に `{ "name": "cust", "source": "formula", "formula": "顧客コード" }` を 1 つ（詳細画面のボタンなら、表示中のレコードの顧客コード）。

## 要点

- **「0 の行」を足すのが肝です。** 元が 0 件になったキーも集計に残るので、件数で処理を分けなくても集計先が 0 で更新されます。
  0 の行を足さずに `GROUP BY` だけで書くと 1 行も出ず、集計先が古い値のまま残ります。
- **消す文も 0 にする文も先に置かない。** 途中で失敗しても、まだ書けていない行が古いまま残るだけで壊れません。
  行を残したくないときは、集計の**あと**に `DELETE … AND 件数 = 0` を置きます（下の「全体再計算」と同じ）。
- **明細（担当者別など）も同じ形にします。** `UPSERT` のキーは dialect 1 では 1 項目だけなので、
  明細アプリに**連結キーの項目**（文字列 1 行・重複を禁止する）を 1 つ用意し、`CONCAT(顧客コード, '-', 担当者)` で作ります。

  ```sql
  -- 4. 集める（明細）。キーは 顧客コード と 担当者 をつないで作る
  CREATE TEMP TABLE #draw AS
  SELECT CONCAT(顧客コード, '-', 担当者) AS 明細キー, 顧客コード, 担当者, 1 AS 件数, 金額
    FROM LAPP_受注 WHERE 顧客コード = @cust
  UNION ALL
  SELECT 明細キー, 顧客コード, 担当者, 0 AS 件数, 0 AS 金額
    FROM LAPP_集計明細 WHERE 顧客コード = @cust;

  -- 5. 集計する
  CREATE TEMP TABLE #dagg AS
  SELECT 明細キー, 顧客コード, 担当者, SUM(件数) AS 件数, SUM(金額) AS 金額
    FROM #draw GROUP BY 明細キー, 顧客コード, 担当者;

  -- 6. 書き込む（既にある行は更新されるので、レコード番号は変わらない）
  UPSERT INTO LAPP_集計明細 (明細キー, 顧客コード, 担当者, 件数, 金額)
  SELECT 明細キー, 顧客コード, 担当者, 件数, 金額
    FROM #dagg
  ON DUPLICATE (明細キー);

  -- 7. 0 件になった行だけを消す（消すのは集計のあと）
  DELETE FROM LAPP_集計 WHERE 顧客コード = @cust AND 件数 = 0;
  DELETE FROM LAPP_集計明細 WHERE 顧客コード = @cust AND 件数 = 0;
  ```

- 並び順を付けるときは **`SUM(…) AS 別名` + `ORDER BY 別名`**（集計式そのものは `ORDER BY` に書けない）。
- 集計先の**詳細画面に関連レコード一覧を置く**と、テーブルと同じ見え方になります。
- **`DELETE` → `INSERT … SELECT` の全置換は勧めません**（2026-10-28 までの標準形。2026-11-03 に差し替えました）。理由は 2 つ:
  ① **先に消す**ので、後ろの文が失敗すると行が消えたまま残る。
  ② 押すたびに行を作り直すので**レコード番号（ID）を使い捨てる**（更新履歴も毎回切れる）。
  **意図して作り直したいときだけ**使ってください。素の `INSERT` に対する注意 `KSQL1305` が出ますが、保存の障害にはしません。


## 月や年をまるごと作り直す（全体再計算）

「その月の請求を、受注から全部作り直す」のように、**キーが 1 つに決まらない作り直し**はこの形です。
消す文も 0 にする文も無いので、途中で失敗しても**前の値のまま残ります**。

```sql
-- @ksql dialect: 1
DECLARE @m = '';

-- 0) 作り直してはいけないものを守る（確定済みの月など）
ASSERT (SELECT COUNT(*) FROM LAPP_請求確定 WHERE 請求月 = @m) = 0, 'この請求月は確定済みです。再計算できません';

-- 1) 集める。元を先に集計し、今の集計先を「0 の行」として足す
CREATE TEMP TABLE #raw AS
SELECT 顧客コード, MAX(顧客名) AS 顧客名, COUNT(*) AS 件数, SUM(金額) AS 金額
  FROM LAPP_受注 WHERE 請求対象月 = @m AND 請求対象 = '対象'
 GROUP BY 顧客コード
UNION ALL
SELECT 顧客コード, '' AS 顧客名, 0 AS 件数, 0 AS 金額
  FROM LAPP_請求 WHERE 請求月 = @m;

-- 2) まとめる（kintone には行かない）
CREATE TEMP TABLE #agg AS
SELECT 顧客コード, MAX(顧客名) AS 顧客名, SUM(件数) AS 件数, SUM(金額) AS 金額
  FROM #raw GROUP BY 顧客コード;

-- 3) 書き込む（元が無くなったキーは 0 の行だけが残るので 0 で更新される）
UPSERT INTO LAPP_請求 (請求キー, 顧客コード, 顧客名, 請求月, 件数, 金額, 集計日時)
SELECT CONCAT(顧客コード, '-', @m) AS 請求キー, 顧客コード, 顧客名, @m AS 請求月,
       件数, 金額, @NOW() AS 集計日時
  FROM #agg
ON DUPLICATE (請求キー);

-- 4) 0 のまま残った行（もう対象でない）を消す
DELETE FROM LAPP_請求 WHERE 請求月 = @m AND 件数 = 0;
```

設定側は、`params` に `{ "name": "m", "source": "input", "formula": "" }` と、`inputs` に請求月を聞く項目を 1 つ。

### 要点

- **元（受注）を先に `GROUP BY` してから `UNION ALL`** する。月ぜんぶが相手なので、明細のまま積むと
  一時テーブルが元の件数ぶんに膨らみます（上限は `limits` の章）。`GROUP BY` は **`UNION ALL` の前の枝にだけ**掛かります。
- 集計先から足す 0 の行は、**文字の項目を `''`** にする。こうすると `MAX()` が元の側の**今の値**を採ります。
- **先に `UPDATE … SET 件数 = 0` で埋める形は勧めません。** 書き込みが 2 倍になり、0 にしたあとで失敗すると
  0 のまま残り、レコードの**更新履歴にも余計な 0 更新**が付きます。
- 消すのは**集計のあと**。先に消すと、消したあとで失敗したときに行ごと無くなります。
- 「もう対象でない行」を `NOT IN (SELECT …)` で消すことは**できません**（`sql` の章）。0 の行を足して
  `件数 = 0` で消すのが、この形を使う理由の 1 つです。
- キーを `CONCAT` で作るときも、**`DELETE` の `WHERE` には関数を書かない**（`sql` の章）。
  1 件ぶんのボタンなら、計算式でキーを組んでパラメーターで渡します。

## イベントに置くときは 1 文にまとめられないか見る

上の標準形は、集計先の行がまだ無い場合にも 0 件になった場合にも効く形です。**イベント起動に置くとき**で、親の行があると分かっていて明細がテーブルなら、`UPSERT` と `APPLY` を 1 文にまとめてください。

```sql
UPDATE LAPP_集計 SET 件数 = …, 売上 = …, 集計日時 = NOW() WHERE 顧客コード = @cust
  APPLY 明細 (REMOVE ALL ROWS; APPEND (担当者, 明細件数, 明細金額) SELECT …);
```

イベントはロックを取らないので、2 文に分けると別の実行と前後したときに**親が新しい時点・明細が古い時点**になり得ます。1 文なら 1 レコードの書き込みなのでずれません。詳しくは `sql` の章の「イベント起動に置く SQL」。

## 明細を「別アプリ」にするか「テーブル」にするか

| | 明細を別アプリ（この節） | 明細をテーブル（`apply`） |
|---|---|---|
| 書き方 | `UPSERT`（0 の行を足す） | 全置換（`REMOVE ALL ROWS` + `APPEND … SELECT`）だけ |
| 見え方 | 関連レコード一覧 | テーブル（帳票にも出せる） |
| 親が複数 | **まとめて処理できる** | **親が 1 件に決まる条件が必須**（複数親は「グループごと」で分ける） |
| ループ | 使える | **使えない**（1 件ずつ回すと最後の 1 件しか残らない） |
| 迷ったら | **こちら**（制約が少ない） | テーブルで見せたい・帳票に出したいとき |

どちらも使えます。**今ある設定が古い全置換の形でも動きます**ので、慌てて書き換える必要はありません。
新しく作るときと、`DELETE` のあとで失敗して困ったときに、上の標準形へ寄せてください。

## 変更前のレコードでも実行する

「集計先のキー（顧客コード）を付け替えた」ときは、**新しい集計先だけ直すと古い集計先が残ります**。
起動に `event_edit`（保存後・編集）があるアクションで **`prevRecord: true`** にすると、
**変更前のレコードでも同じ SQL を 1 回実行**するので、前の集計先も直ります（パラメーターは変更前の値で評価）。
