# SQL の規約（許す文・パラメーター・関数・行ごとの書き戻し・JOIN の読み方）

エンジンは **kSQL（`@rex0220/kintone-sql-tools`）の Flow dialect 1**。SQL は**アクションごとに 1 本**。

- 1 行目に **`-- @ksql dialect: 1`**。
- **50 文まで**（`DECLARE` も 1 文と数える）、**同時に置ける一時テーブルは 30 個まで**（`DROP TEMP TABLE` で外した表は数えない）、**1 本 20,000 字まで**。超えた SQL は kact_check が止める。
- アプリは**論理アプリ名 `LAPP_<名前>`** で書く（共通設定の対応表。実アプリ ID を SQL に書かない）。
- 項目は**項目コード**（ラベルではない）。`$id` はレコード ID、`$revision` はリビジョン。

## 許す文 / 拒否する文

| 区分 | 文 |
|---|---|
| **許す** | `DECLARE`、`SET`、`CREATE TEMP TABLE`、`DROP TEMP TABLE`、`ASSERT`、`EXIT`、`INSERT … VALUES`、`INSERT … SELECT`、`UPDATE`、`DELETE`、`UPSERT` / `MERGE`、`REORDER`、および `apply` の形の `APPLY` |
| **拒否** | **トップレベルの `SELECT` / `WITH`**（結果の表示先がない）、`SHOW`、`DESCRIBE`、`EXPLAIN`、`VALIDATE ONLY`、`IMPORT`、CSV 系、**サブテーブルへの直接の DML**（`INSERT INTO アプリ$テーブル`）、`apply` の形以外の `APPLY` |

表に無い種類は**保存時に拒否**します（fail-closed）。`SELECT` は、許す文の中（`INSERT … SELECT`、`SET @x = (SELECT …)`、CTE、サブクエリ、一時テーブル）でだけ使えます。

**`DELETE` と `UPDATE` には `WHERE` が必須**です（全件を書き換えるのを防ぐため）。
`DELETE FROM LAPP_集計;` は「DELETE 文には WHERE 句が必須です」、
`UPDATE LAPP_受注 SET 担当者 = '';` は「UPDATE 文には WHERE 句が必要です（全件更新を防ぐため）」で、
どちらも `pParse` で**保存できません**。

**本当に全件に当てたいときは、その意図を条件に書きます**（`WHERE $id > 0`）。
集計アプリを作り直す `DELETE FROM LAPP_集計 WHERE $id > 0;` や、
全件の項目を空にする `UPDATE LAPP_受注 SET 担当者 = '' WHERE $id > 0;` がその形です。
**`WHERE` を省いて全件に当てる道はありません**。だから実行計画に `predicate` の無い書き込みの文は出ません
（全件に当たる形は `kintone query: $id > 0` として見えます）。

## パラメーター（`DECLARE` の外部注入）

```sql
DECLARE @cust = '';          -- 既定値つきで宣言する
DECLARE @_selected = [];     -- 配列（「まとめて 1 回」「グループごと」の予約名）
```

- 注入するのは**その SQL が `DECLARE` している名前だけ**。設定の `params` / `inputs` と**過不足なく 1 対 1**（予約名は自動）。
  片方にしか無ければ**保存時エラー**です。
- 名前は `[A-Za-z_][A-Za-z0-9_]*`、64 字まで、**大文字小文字を無視して一意**。予約名（`_` 始まり）は設定に書けません。
- 値は**文字列として束縛**されます（文字列連結ではないので SQL インジェクションは起きない）。数値項目との比較は数値として効きます。
- **置ける場所**: `WHERE` / `HAVING` の比較右辺、`IN (@a, @b)`、`UPDATE` の `SET` 値、`ASSERT` のオペランド、`SELECT` の定数列、`KLIKE` の右辺。
  **`VALUES` の直接の要素には置けません** → `INSERT INTO … SELECT @x AS 列` の形で書く。
- 空の扱い: 必須の入力が空 = 実行前エラー。任意の入力が空 = **注入しない**（`DECLARE` の既定値が使われる）。計算式が空文字 = 空文字を注入。
- 型: 注入できるのは**文字列**（と予約名 `_selected` の**文字列の配列**）だけ。`null` / 真偽値 / `NaN` は実行前エラー。
  日付は `YYYY-MM-DD`、日時は ISO 8601（タイムゾーン付き）。

### 予約パラメーター

| 名前 | 値 | 使える種類 |
|---|---|---|
| `_app` | 自アプリ ID | すべて |
| `_user` | ログインユーザーのコード | すべて |
| `_record` | 処理対象のレコード ID | レコード / 一覧の「1 件ずつ」 |
| `_status` / `_prev_status` | 変更後 / 変更前のステータス | `event_status` のみ |
| `_selected` | 選んだレコードの `$id` の**配列** | 一覧の「まとめて 1 回」「グループごと」（`IN @_selected` でだけ使う） |
| `_group` | 分ける式の値 | 一覧の「グループごと」のみ |

## 相対日付

`RELATIVE_DATE` 注釈つきの `DECLARE` には、**許された日付関数のトークンだけ**を渡せます。
置ける場所は **`WHERE` の比較右辺と `BETWEEN` だけ**で、`SET` の値には使えません。
設定側は入力項目の `type: "relative_date"` と対にします。

## as-of 関数

`@NOW()` / `@TODAY()` は**起動 1 回につき 1 回だけ**決まり、一覧の全レコード・検証・実行で同じ値を使います。
基準のタイムゾーンは共通設定の `timezone`。`APPEND … SELECT` のソースでも使えます。

## ガードと「何度流しても同じ結果」

**形**（メッセージは `,`（コンマ）で続けます。**`MESSAGE` という語はありません**）:

```
ASSERT [WARN] <式> <比較演算子> <式> [, 'メッセージ'];
ASSERT [WARN] <式> BETWEEN <式> AND <式> [, 'メッセージ'];
EXIT SUCCESS IF <同じ形の条件>, 'メッセージ';
```

```sql
ASSERT (SELECT COUNT(*) FROM LAPP_受注 WHERE 顧客コード = @cust) > 0, '対象の受注がありません';
ASSERT @cust <> '', '顧客コードがありません';
EXIT SUCCESS IF (SELECT COUNT(*) FROM LAPP_受注 WHERE 処理状況 <> '済') = 0, '対象がありません';
```

- `ASSERT` のメッセージは**省けます**が、`EXIT SUCCESS IF` の**メッセージは必須**です（無いと `pParse`）。
- `WARN` を付けると、条件が不成立でも**警告として続行**します（止めたいときは付けない）。
- 条件に書けるもの: 数値・**文字列リテラル**（`''` も可）・パラメーター（`@cust`）・算術式・スカラーサブクエリ。
  **書けないもの**（どれも `pParse`）:
  - **フィールド参照**（`FROM` が無いため）。レコードの値を見るならスカラーサブクエリにする
  - **`AND` / `OR` の複合条件** → `ASSERT` を**複数の文に分ける**
  - **条件全体を括弧で包む**（`ASSERT (@cust <> '') , '…'`）。括弧は算術式と読まれ、中は数値だけです
  - 裸の値（`ASSERT 1`）
- キーが空のときに止めるだけなら、`ASSERT` ではなく**実行条件**（`execCond` ＋ `execNgMessage`）でも書けます。
  押す前に止まって理由も出せるので、こちらのほうが利用者には親切です（`formula` の章）。
- **`ASSERT` で守れるのは「書いた条件」だけです。** 打ち間違いや空のパラメーターは止まりません。
  入力の必須・実行条件・**書き込み上限**とそろえて考えます（`config` の「不備で大量に書き換えないための 4 段」）。
- **`ASSERT` のメッセージは画面に出ます**（この製品で文を画面に出す唯一の例外）。
  だから**メッセージに業務データの値をじかに書かない**（「対象がありません」のような固定の文にする）。
- **メッセージに `{@名前}` と書くと、その SQL で `DECLARE` した変数の値が入ります**（`ASSERT` / `EXIT SUCCESS IF` / `ASSERT WARN`。
  固定の文でも共通の文 `@m_…` でも同じ）。例: `'{@year} 年の受注が多すぎます'` → 画面は「2026 年の受注が多すぎます」。
  - 入れられるのは**パラメーター・入力・予約パラメーター**（`DECLARE` したもの）。注入していないときは `DECLARE` の既定値
  - **入れられないもの**（保存時エラー `pMessagePlaceholder`）: `SET` で SQL の中で作った値（件数など。プラグインから見えない）・
    配列（`_selected`・キーの配列）・共通の文。打ち間違いも同じエラーになる
  - 名前は大文字小文字を区別しない。差し込んだ値の中の `{@…}` は読み直さない
  - **計算式の口（`execNgMessage` / `resultMessage`）では置き換わりません**（`REPLACE($m_x, "{n}", …)` を使う。`config` の章）
- 止まったときの画面は「アクション名: メッセージ」の次の行に**書いた件数**（「書き込みはしていません。」など）が付きます。
  文番号は出ません。
- 何度流しても同じ結果になる形で書く（`patterns` の標準形がその形です）。強い順に
  **① 0 の行を `UNION ALL` で足して集計し `UPSERT`**（消す文も 0 にする文も無いので、途中で失敗しても壊れない）、
  **② `UPSERT … ON DUPLICATE`**、**③ `DELETE` → `INSERT … SELECT` の全置換**（消したあとで失敗すると空のまま残る）。

### 読む前に件数を数えて止める（読み取りの上限の手前で、業務の言葉で止める）

読み取りの上限（`limits.readMax`。既定 10,000）を超えると、画面には決まった文
（「読む件数が上限（10,000 件）を超えるため、中止しました。…」）が出ます。
**業務の言葉で先に止めたい**ときは、読む前に `COUNT(*)` だけを `ASSERT` で見ます。

```sql
DECLARE @year = '';
DECLARE @m_too_many = '';   -- 共通の文: 「{@year} 年の受注が 1 万件を超えているため、月で分けてください」
ASSERT (SELECT COUNT(*) FROM LAPP_受注 WHERE 年 = @year) <= 10000, @m_too_many;
```

- `COUNT(*)` だけ（`WHERE` は kintone に渡せる条件だけ・`GROUP BY` なし）の `ASSERT` / `EXIT` のサブクエリと、
  一時テーブルの元は、**件数を 1 回聞くだけ**でレコードを読みません（読み取りの上限に掛からない。エンジン 3.93.0 以降）。
- **上限は `10000` のように数で書く**。`'10000'` や文字列で宣言した変数（`DECLARE @limit = '10000';`）と大小比較すると
  **実行時にエラーで止まります**（数値と文字列の混在。桁の違いで誤判定しないため）。変数にするなら `DECLARE @limit = 10000;`。
- 上限の数は SQL に書くので、共通設定の `readMax` を変えたら合わせて直す。

## イベント起動に置く SQL（必ず守る）

保存後・ステータス変更のイベントで動かすアクションは、**ロックを取りません**（仕様 §10.4）。イベントには押し直す人がいないので、止めると「やらなかったこと」が誰にも伝わらないまま、データだけが先に進むからです。kintone の関連レコード集計と同じ考え方です。

そのかわり、**イベントに置く SQL は差分を足し引きせず、関係する範囲を毎回まるごと計算し直して反映する**形で書いてください。関連レコード集計が、1 レコードの変更で関係するレコード全体を集計し直すのと同じです。こう書けば、同じレコードを何度保存しても、ほかのレコードと前後しても、最新の正しい結果に落ち着きます。

| 書き方 | 可否 |
|---|---|
| 0 の行を `UNION ALL` で足して集計し `UPSERT` | ◎ 消す文も 0 にする文も無いので、途中で失敗しても壊れない（`patterns` の「全体再計算」） |
| `UPSERT … SELECT … ON DUPLICATE (キー)` | ○ キーの行を計算し直して上書きする |
| `DELETE` → `INSERT … SELECT`（全置換） | ○ ただし消したあとで失敗すると空のまま残る |
| `REMOVE ALL ROWS` + `APPEND … SELECT`（テーブル） | ○ |
| 消さずに足すだけの `INSERT` / `INSERT … SELECT` | **×** 保存のたびに増える |
| `SET 売上 = 売上 + 1` のような自分自身の足し引き | **×** 差分の反映になる |

**`UPSERT` / `MERGE` のキーにできる項目は限られます。** **重複禁止を設定した「文字列 1 行」か「数値」だけ**です。
**ドロップダウンなどの選択肢の項目はキーにできません**（実行時に `ArgumentError`。保存の検査では止まりません）。

- **ステータス別・区分別に集計する**ときは、集計先の**キーを文字列 1 行（重複禁止）**にして、
  そこにステータスや区分の名前を入れます。
  文字列なので選択肢の読み替えも起きず、**既定の名称がそのまま入る**＝言語に依らないキーになります
- 見せ方を変えたいなら、キーとは**別に**選択肢の項目を持たせて、そちらに書きます

```sql
DECLARE @_status = '';
DECLARE @_prev_status = '';

-- ステータス変更イベントで、変更前と変更後のステータスだけ数え直す
UPSERT INTO LAPP_集計 (状態, 件数)
SELECT ステータス AS 状態, COUNT(*) AS 件数
  FROM LAPP_受注
 WHERE ステータス IN (@_status, @_prev_status)
 GROUP BY ステータス
ON DUPLICATE (状態);
```

`状態` は**文字列 1 行（重複禁止）**です。`ステータス` を `SELECT` すると**既定の名称**が返り、
`GROUP BY` のキーにもそのまま使えます。`WHERE` に書く値も既定の名称でよく、
**kintone へ送るときにプラグインが表示名へ読み替えます**（kintone の絞り込みは表示名しか受けません）。

**親の値とテーブルは、できれば 1 文にまとめてください。** 親の行があると分かっているなら `UPSERT` と `APPLY` を分けずに書けます。

```sql
UPDATE LAPP_集計 SET 件数 = …, 売上 = … WHERE 顧客コード = @cust
  APPLY 明細 (REMOVE ALL ROWS; APPEND (担当者, 明細件数, 明細金額) SELECT …);
```

1 文なら 1 レコードの書き込みになるので、別の実行と前後しても**親と明細がずれません**。2 文に分けると、親が新しい時点・明細が古い時点、ということが起こり得ます（明細を別アプリに持つときは分けるしかないので、`patterns` の標準形で書きます）。

これらは `kact_check` と保存のツールが**警告**として見ます（保存は止まりません）。

| コード | 意味 |
|---|---|
| `wEventAppend` | イベントに置いたのに、消さずに足すだけの `INSERT` がある |
| `wEventDelta` | 同じ項目を足し引きする代入がある |
| `wEventTwoStep` | 同じアプリの親の値とテーブルを別の文で書いている |

ボタンと一覧の一括はこれまでどおりロックを取るので、この規則はイベントに置くときだけの話です。

## 保存前の検査（`check_create` / `check_edit` / `check_delete`）

保存（削除）の**直前**に読むだけの SQL を流し、**`ASSERT` で止まったらその文を画面の上に出して、保存（削除）を取り消します**。
保存後のイベントでは止められない「締め処理中の月に実績を足させない」のような用途に使います。

```sql
DECLARE @m = '';   -- パラメーター（source: "formula"）: DATE_FORMAT(日付, "YYYY-MM", "Asia/Tokyo")
ASSERT (SELECT COUNT(*) FROM LAPP_締め管理 WHERE 年月 = @m AND 区分 IN ('締め処理中', '完了')) = 0,
       '{@m} は締め処理中または締め済みのため、追加・変更できません';
```

- **書けるのは `DECLARE` / `SET` / `CREATE TEMP TABLE` / `DROP TEMP TABLE` / `ASSERT` / `EXIT` だけ**。
  `INSERT` / `UPDATE` / `DELETE` / `UPSERT` / `MERGE` / `REORDER` / `APPLY` は `pCheckWrite` で保存できません（実行時も書き込みを断ります）。
- **保存する前の画面の値は、パラメーターの計算式で渡します。** SQL で自分のレコードを読むと**前回の値**で、追加ではまだありません（`@_record` は空文字）。
- **一覧のインライン編集では、自動計算・計算の項目が古い値**です（kintone の制限）。年月などは**日付から式で作ります**（上の例）。
- 検査が最後まで流れなかったとき（権限・通信・SQL の誤り・制限時間）も**保存を止めます**。読む先のアプリの権限を、保存する人全員に付けてください。
- `EXIT SUCCESS IF` と `ASSERT WARN` は通します（保存する）。実行条件（`execCond`）が偽なら検査しません。
- 同じ起動に検査が複数あれば設定の順に流し、最初に止まったところで取り消します。
- REST API・CSV 読み込みでは動きません（止められません）。

## 関数（`SELECT` の列で使えるもの）

`CREATE TEMP TABLE … AS SELECT` と、`INSERT … SELECT` / `UPSERT … SELECT` の **`SELECT` の列**で使えます。
**書き込む文の `WHERE` には書けません**（「書くときに間違えやすいところ」）。値を直してから比べたいときは、先に一時テーブルで直します。

| 種類 | 関数 |
|---|---|
| 文字 | `TRIM` / `LTRIM` / `RTRIM`、`UPPER` / `LOWER`、`LENGTH`、`SUBSTRING(値, 開始 [, 長さ])`（1 から数える）、`LEFT` / `RIGHT(値, 文字数)`、`INSTR(値, 探す文字)`、`CONCAT(値1, 値2, …)`、`REPLACE(値, 探す文字, 置き換え)`、`LPAD` / `RPAD(値, 長さ [, 埋める文字])`、`TRANSLATE(値, 変換元, 変換先)` |
| 正規表現 | `REGEXP_LIKE(値, パターン)`、`REGEXP_REPLACE(値, パターン, 置き換え)`、`REGEXP_SUBSTR(値, パターン)`（JavaScript の正規表現） |
| 空の扱い | `COALESCE(値1, 値2, …)`、`ISNULL(値, 代わり)`、`NULLIF(値1, 値2)`、`GREATEST` / `LEAST(値1, 値2, …)` |
| 数 | `ROUND` / `FLOOR` / `CEIL` / `TRUNCATE(値 [, 桁])`、`ABS`、`MOD(値, 割る数)`、`POWER`、`SQRT` |
| 型 | `CAST(値 AS NUMBER)`、`CAST(値 AS TEXT)`（**日付の型はありません**） |
| 日付 | `YEAR` / `MONTH` / `DAY`、`DATE_FORMAT(日付, '%Y-%m-%d')`、`DATE_ADD(日付, 数, 'DAY')`（`'MONTH'` / `'YEAR'` も）、`DATEDIFF(日付1, 日付2)`、`LAST_DAY(日付)`、as-of 関数（上の章） |
| 集計 | `COUNT(*)`、`SUM`、`MAX`、`MIN`、`AVG`（`GROUP BY` と一緒に） |

**表に無い名前を当てにいかない。** 無い関数は保存のときに `pParse` で止まります。くわしい引数と例は
[kSQL 言語リファレンス](https://qiita.com/rex0220/items/e089fddf4229d74be699)の「文字列・数値関数」にあります。
**`DATE_FORMAT` の書式は、SQL では `'%Y-%m-%d'`、計算式では `"YYYY-MM-DD"`** です（別のエンジンなので書き方が違います）。

**関数の動きを試す道具は、このツールにはありません**（`kact_try` は計算式だけ、`kact_explain` は実行しません）。
下の表は実物のエンジンで確かめた動きです。表に無い使い方は「実機の少ない行で確かめてください」と利用者に伝えます。

| 書いたもの | 結果 | 気をつけること |
|---|---|---|
| `REGEXP_LIKE('12', '^[0-9]+$')` | 文字の `'1'`（合わなければ `'0'`） | 真偽ではありません。**`CASE WHEN REGEXP_LIKE(…) = '1' THEN`** と比べます（比べないと `pParse`「比較演算子が必要です」） |
| `TRANSLATE('ＡＢ１２', 'ＡＢ１２', 'AB12')` | `'AB12'` | 1 文字を 1 文字に置き換えます。変換元と変換先の**文字数が違うとエラー**。全角の英数字を半角にするときは、両方の並びをそろえます |
| `TRIM('  a　')` | `'a'` | 前後の空白は、全角の空白も取ります |
| `CAST('007' AS NUMBER)` | `7` | `CAST(CAST('007' AS NUMBER) AS TEXT)` で `'7'` |
| `CAST('abc' AS NUMBER)` | `'abc'`（**そのまま通る**） | 止まりません。**先に `REGEXP_LIKE` で数字の形かを確かめます**。空は `0` になります |
| `DATE_ADD('2026-02-30', 0, 'DAY')` | `2026-03-02`（**繰り上がる**） | 実在しない日付を止めません。`2026-13-01` も `2027-01-01` になります |
| `DATE_FORMAT('2026-13-01', '%Y-%m-%d')` | `'2026-13-01'`（そのまま） | 実在するかの検査には使えません |

**日付が実在するか**は、形を確かめてから、`DATE_ADD` で 0 日足した値が元と同じかで見分けます。

```sql
-- 日 = 文字の項目から作った 'YYYY-MM-DD' のつもりの値。実在すれば 実在 = '1'
CREATE TEMP TABLE #u AS
SELECT rid, 日,
       CASE WHEN REGEXP_LIKE(日, '^[0-9]{4}-[0-9]{2}-[0-9]{2}$') = '1'
            THEN CAST(DATE_ADD(日, 0, 'DAY') AS TEXT) ELSE '' END AS 足した
  FROM #t;
CREATE TEMP TABLE #v AS
SELECT rid, 日, CASE WHEN 足した != '' AND 足した = 日 THEN '1' ELSE '0' END AS 実在 FROM #u;
```

## 行ごとに違う値を書き戻す（`UPDATE … FROM #一時テーブル`）

**行ごとに違う結果（検査の結果・計算した値）を、読んだ行そのものに書き戻す**ときの形です。
結果を一時テーブルに作り、**レコード ID（`$id`）で突き合わせて** `UPDATE` します。
**重複禁止の項目が無いアプリでも書けます**（`UPSERT` と違って、キーの項目は要りません）。

```sql
-- @ksql dialect: 1
-- 1. 対象の行を読み、行ごとの結果を一時テーブルに作る（rid = レコード ID）
CREATE TEMP TABLE #r AS
SELECT $id AS rid,
       CASE WHEN TRIM(数量) = '' THEN '誤りあり' ELSE '検査OK' END AS 結果,
       CASE WHEN TRIM(数量) = '' THEN '数量が空です。' ELSE '' END AS 理由
  FROM LAPP_取込 WHERE 状態 NOT IN ('登録済み');

-- 2. 一時テーブルの値を、レコード ID で突き合わせて書き戻す
UPDATE LAPP_取込
   SET 状態 = r.結果, 誤り内容 = r.理由
  FROM #r AS r
 WHERE LAPP_取込.$id = r.rid;
```

| 決まり | 中身 |
|---|---|
| ソース | 一時テーブル（`FROM #名前 AS 別名`）。サブクエリと CTE は書けません |
| 突き合わせ | **等値 1 つだけ**。`アプリ.$id = 別名.列` か、文字列（1 行）・数値の項目どうし |
| ソースの重なり | 同じキーの行がソースに 2 つあると、**書く前にエラー**で止まります（どちらを書くか決まらないため）。`GROUP BY` で 1 行にしておきます |
| `SET` の右辺 | **`別名.列` か固定の値**。関数は書けないので、直した値は一時テーブルの列に作っておきます |
| 書ける型 | 文字・数値・日付・ドロップダウンなどの **1 つの値**。チェックボックス・複数選択・ユーザー選択・添付ファイル・テーブルは書けません |

> **行を作り直す形（結果を付けた新しい行を `INSERT` して、古い行を `DELETE`）にしないでください。**
> レコード番号が押すたびに変わり、元の値・コメント・変更履歴が消えます。途中で止まると新旧の行が両方残ります。
> 「重複禁止の項目が無いから `UPSERT` で書けない」ときに使うのが、この `UPDATE … FROM` です
> （2026-11-12 の試行で、この形を知らずに行を作り直す設定が出来ました）。

## 別のアプリと突き合わせる（`JOIN` が相手をどう読むか）

「マスタにあるか」「登録先にもうあるか」を見るとき、**書き方で相手のアプリの読み方が変わります**。

| 書き方 | 相手のアプリの読み方 |
|---|---|
| **一時テーブルを `FROM` に置いて、アプリへ `INNER JOIN`** | **キーを kintone の `in (…)` に載せて、当たる行だけ読みます**（重複を除いて **300 キーまで**。超えると全件） |
| 一時テーブルからアプリへ `LEFT JOIN` | **全件**を読みます |
| `WHERE 項目 IN (SELECT … FROM アプリ)` | **全件**を読みます |

- **`ON` に書ける条件は等値 1 つだけ**です（`ON a = b AND c = d` は `pParse`）。2 つの項目で突き合わせるときは、
  `CONCAT(a, '/', c)` で 1 つの列にしてから結合します。
- 全件を読む形は、相手が読み取りの上限（`readMax`。既定 10,000 件）を超えると**止まります**。
  **増えていくアプリ（受注・実績など）は、必ず 1 行目の形で読みます。**
- **キーは空を除き、`GROUP BY` で重複を除いた一時テーブルにします。** 300 キーを超えないように、
  対象の行数を先に `ASSERT` で数えて止めます（「読む前に件数を数えて止める」）。
- **「もうあるか」を、日付の範囲や「直近 1 年」で読んで確かめないでください。**
  範囲の外に同じキーがあると見落として、**二重の登録や上書き**になります。キーで読みます。
- **`UPSERT` は、既にある行を上書きします。** 「既にあるものには触らず、無いものだけ足す」には使えません。
  下の形（在るキーを読む → 当たらない行だけ `INSERT`）にします。
- **実行計画には `read …: 不明（上限 maxRecords=10000 と仮定…）` と出ます。** キーの数は実行時に決まるためで、
  **全件を読むという意味ではありません**（`kintone query: (全件取得)` と出るのは、条件の無い読み取りです）。

```sql
-- @ksql dialect: 1
-- 1. 対象の行と、突き合わせるキー（受注番号-行番号）
CREATE TEMP TABLE #w AS
SELECT $id AS rid, CONCAT(TRIM(受注番号), '-', TRIM(行番号)) AS キー
  FROM LAPP_取込 WHERE 状態 NOT IN ('登録済み');

-- 2. 相手のアプリに「在るキー」を、今回のキーで絞って読む（一時テーブルを FROM に置く INNER JOIN）
CREATE TEMP TABLE #k AS SELECT キー FROM #w WHERE キー != '' GROUP BY キー;
CREATE TEMP TABLE #o AS
SELECT o.明細キー FROM #k AS k INNER JOIN LAPP_受注 AS o ON k.キー = o.明細キー;

-- 3. 当たらなかった行（まだ無い行）を、一時テーブルどうしの LEFT JOIN で見分ける（当たらないと相手の列が空）
CREATE TEMP TABLE #r AS
SELECT w.rid, w.キー,
       CASE WHEN o.明細キー != '' THEN '登録済み' ELSE '検査OK' END AS 結果,
       CASE WHEN o.明細キー != '' THEN '既に受注にあります' ELSE '' END AS 理由
  FROM #w AS w LEFT JOIN #o AS o ON w.キー = o.明細キー;

-- 4. 行ごとの結果を書き戻す（上の章）
UPDATE LAPP_取込
   SET 状態 = r.結果, 処理結果 = r.理由, 明細キー = r.キー
  FROM #r AS r
 WHERE LAPP_取込.$id = r.rid;
```

無い行だけを足すなら、3 の後に `INSERT INTO LAPP_受注 (…) SELECT … FROM #r WHERE 結果 = '検査OK';` を書きます
（素の `INSERT` なので注意 `KSQL1305` が出ます。在るキーを先に外しているので重なりません。登録先のキーを重複禁止にしておけば、もしものときも kintone が断ります）。

## 注意（warning。保存は止まらない）

| コード | 意味 | どうするか |
|---|---|---|
| `KSQL1305` | 素の `INSERT` は再実行で重複し得る | 全置換（`DELETE` → `INSERT … SELECT`）では避けられない。利用者に伝えるだけ |
| `KSQL1307` | `APPLY` の親の `WHERE` が 1 件に決まると読めない | キーを「値の重複を禁止する」にする。できないなら、重複時は実行時に止まることを伝える |
| `wEventAppend` | イベントに置いたのに、消さずに足すだけの `INSERT` がある | `UPSERT` か「`DELETE` してから `INSERT`」に書き替える（上の章） |
| `wEventDelta` | 同じ項目を足し引きする代入がある（`売上 = 売上 + 1`） | 元のデータから毎回計算し直す形にする |
| `wEventTwoStep` | 同じアプリの親の値とテーブルを別の文で書いている | できれば 1 文（`UPDATE … SET … APPLY …`）にまとめる |

知らないコードが来ても**エラー扱いにしない**（エンジンが診断を増やすため）。`kact_check` の `findings` の `level` に従います。

## 書くときに間違えやすいところ

- **`ORDER BY` に集計式そのものは書けません。** `SUM(金額) AS 売上` と別名を付けて `ORDER BY 売上` と書く
  （集計式を直接書くと parse エラー `KSQL1202`）。
- `GROUP BY` でキーをまとめると、**集計元が 0 件のときに 1 行も出ません**（集計先が古い値のまま残る）。`patterns` の形にする。
- **`NOT IN` は、中身が値のリスト（`確定 NOT IN ('確定')`）や配列（`NOT IN @keys`）なら書けます。**
  kintone の `not in` にそのまま乗るので、書き込む文の `WHERE` でも使えます。ただし**空配列の `NOT IN` は全件**に当たります
  （「選択が空なら何もしない」は `IN @_selected` 側で書く）。書けないのは次の**サブクエリの形だけ**です。
- **`NOT IN (SELECT …)` は、書き込む文（`UPDATE` / `DELETE`）の `WHERE` に書けません。** 検査は通りますが、
  実行計画で `WHERE predicate cannot be represented by kintone REST (… reason=WHERE_RESIDUAL)` と出て止まります
  （一時テーブル相手でも `temp table references in DELETE are not supported yet`）。
  「もう対象でない行を消す」は、**0 の行を足して集計し、`件数 = 0` で消す**形にします（`patterns` の「全体再計算」）。
  読み取りの `SELECT`（`CREATE TEMP TABLE … AS SELECT` のソース）には書けますが、**JavaScript 側の判定**になり、
  その取得が `EXACT` から `PREFILTERED` に落ちます（相手のアプリをもう 1 回読む）。
- **`IN (SELECT …)` も、書き込む文の `WHERE` には書けません**（一時テーブル相手でも）。`UPDATE … WHERE $id IN (SELECT rid FROM #t)` は
  **検査を通って、実行時に** `temp table references in UPDATE are not supported yet` で止まります。
  一時テーブルの行に合わせて書くなら **`UPDATE … FROM #t`**（「行ごとに違う値を書き戻す」）、選んだレコードなら `$id IN @_selected` です。
- **`REGEXP_LIKE` は `'1'` / `'0'` の文字を返します。** `CASE WHEN REGEXP_LIKE(…) THEN` は `pParse`（比較演算子が必要です）。
  `CASE WHEN REGEXP_LIKE(…) = '1' THEN` と書きます（「関数」の章）。
- **`UPSERT` は既にある行を上書きします。** 「無いものだけ足す」は「別のアプリと突き合わせる」の形にします。
- **`WHERE` に関数を書くと実行時に落ちます**（`DmlConvertError`）。`DELETE … WHERE 請求キー = CONCAT(@cust, '-', @m)` は不可で、
  キーは**計算式で組んでパラメーターで渡します**（`WHERE 請求キー = @key`）。**`SELECT` の列に書く `CONCAT()` は問題ありません。**
- **`FROM (SELECT … UNION ALL …)` の入れ子（導出表）は書けません。** `UNION ALL` は `CREATE TEMP TABLE` に受けます。
- **`GROUP BY` は `UNION ALL` の前の枝にだけ掛かります。** 枝ごとに集計したいときは、それぞれの枝に書きます。
- 別アプリは**自アプリと同じ領域**（通常領域どうし・同じゲストスペースどうし）だけ。
- **選択肢とステータスには「既定の名称」を書きます。** `kact_fields` が返す `options` が既定の名称です
  （`lang` を付けずに取っているため）。kintone の「**言語ごとの名称**」で選択肢やステータスに
  言語ごとの表示名を設定している項目でも、**SQL は変えません**。プラグインが実行時に利用者の言語へ
  読み替えます（エンジン 3.91.0 の `optionNames: "canonical"`）。
  **表示名のほうを書くとエラーにならず 0 件**になるので、`kact_fields` に出ている値をそのまま使ってください。
  **計算式の口（`showCond` / `execCond` / パラメーター / 結果メッセージ）も同じ**です
  （エンジン 3.92.0 の `createRecordNormalizer` で、計算式に渡すレコードも既定の名称にそろえてあります）。

> **利用者は表示名で言ってきます。** 「ラジオボタンが『サンプル１』のものは除いて」と頼まれても、
> `kact_fields` の `options` が `sample1` / `sample2` なら、**`サンプル１` は設定に書けません**。
> **言われた値が `options` に無かったら、表示名を疑ってください。**
> 勝手に読み替えず、**どの既定の名称のことかを利用者に確かめる**か、
> **読み替えたことを伝えて**ください（`kact_fields` は `lang` を付けずに取るので、
> 表示名と既定の名称の対応表はツールからは読めません）。
>
> SQL に表示名を書くと注意 **`choice-unknown`** が出ます。
> **計算式の口に書いても今は何も出ません**（静的な検査は SQL だけを見ています）。
> 計算式のほうが見つけにくいので、こちらこそ気をつけてください。

## 実行計画（`kact_explain`）

書いた SQL が**どう動くか**は、取り込む前に `kact_explain` で見られます（文ごとに 種類・読むアプリ・kintone に投げる条件・
使う項目・API の見積もり）。`kact_check` が見るのは**形と規則**なので、次のような「規則としては正しいが意図と違う」ものは計画で気づきます。

- `WHERE` が kintone の条件にならず**全件取得**になっている（`kintone query: (全件取得)`）
- 書き込む文の `WHERE` に kintone へ渡せない条件が残っていて**止まる**（`reason=WHERE_RESIDUAL`。`NOT IN (SELECT …)` など）
- 読む件数の見積もりが大きい（`estimated API consumption` の `read`）
- 文の順番が思っていたのと違う（集計してから更新のつもりが、更新してから集計になっている）

**見積もりの「不明」は、止まるという意味ではありません。**

- `read …: 不明（上限 maxRecords=10000 と仮定…）` は、**読む件数が実行時に決まる**文に出ます
  （一時テーブルからの `JOIN`、`IN @配列`）。一時テーブルを `FROM` に置いた `INNER JOIN` は、実行時にキーで絞って読みます
  （「別のアプリと突き合わせる」）。
- `write: 不明（上限 dmlMaxRows=100 と仮定…）` は **1 回の通信の件数**の見積もりです。100 件を超える書き込みは
  **100 件ずつに分けて送ります**（書ける合計を決めるのは `writeLimit`）。

**書き込む SQL は、アクションごとに見てください。** 1 本だけ見て通ったつもりになると、もう 1 本の同じ誤り
（`WHERE` の関数など）を見落とします。

**kintone には行きません**（`kact_fields` で控えた項目定義だけを使い、レコードは読みません）。控えの無いアプリがあると
その番号を知らせるので、`kact_fields` で取ってからもう一度見てください。
