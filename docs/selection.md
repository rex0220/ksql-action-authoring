# 一覧の選択の渡し方（`selectionMode`）

**`onList: true`**（種類 `record` で「一覧でも使う」）のアクションだけの設定です（2026-10-31 に種類 `list` をやめた）。利用者は一覧で「選択したレコードのみ一括処理」で選んでからボタンを押します。
開始時に**選択 ID をその場で確定**します（重複を除き `$id` の昇順。以後の選択変更は影響しません）。

| 値 | 動き | `_record` | `_selected` | `_group` | レコードの項目を使う計算式 |
|---|---|---|---|---|---|
| `"loop"`（既定） | 選んだレコードを**1 件ずつ**実行 | 使える | **使えない** | — | 使える |
| `"once"` | **まとめて 1 回**だけ実行 | 使えない | 使える（配列） | — | **使えない** |
| `"group"` | **分ける式の値ごと**にまとめ、グループの数だけ実行 | 使えない | 使える（そのグループの ID） | 使える | **分ける式だけ**レコードごとに評価 |

## 1 件ずつ（`loop`）

- パースは 1 回、レコードごとに実行の文脈を作り直します（`_record` が入れ替わる）。
- 開始前に「m 件に対して実行します」の確認 1 回。各レコードの確認は自動で承認し、**書き込み上限だけ**を見ます。
- **書き込み上限は選択全体の累計**。超えた時点でそのレコードを書かずに失敗にし、**ループ全体を止めます**（以降は未処理）。
- それ以外の失敗（SQL エラーなど）は `listOnError`（続行 / 停止）に従います。進捗は「n / m 件」、中止はレコードの境界で効きます。
- 目安は約 0.7 秒／件・API 4 回／件（300 件で 3〜4 分）。上限は `limits.listBulkMax`（既定 300）。

## まとめて 1 回（`once`）

- 選んだ `$id` を **`_selected` に配列で注入し、実行は 1 回だけ**。SQL は `DECLARE @_selected = [];` と `WHERE $id IN @_selected`。
- **レコード文脈がありません**（アプリアクションと同じ）。`_record` やレコードの項目を使う計算式は**保存時に拒否**されます。
  入力項目（実行時に聞く値）は使えます。
- 確認・上限・ログ・結果メッセージは**1 回ぶん**。
- **選べる件数の上限は min(`limits.listBulkMax`, 200)**（200 はエンジンの推奨値）。超えたら実行前に断ります。
- **この形が要る場面**: テーブルの全置換（`apply`）、「選んだ複数を 1 つの親に入れる」、1 回のクエリでまとめて集計したいとき。
- 空の選択では実行しません。なお**空配列の `NOT IN` は全件**になるので、絞りは `IN @_selected` 側に書いてください。

## グループごと（`group`）

- **分ける式**（`groupFormula`。計算式）を**選んだレコードごとに評価**し、同じ値のものを 1 グループにします。
  グループの数だけ「まとめて 1 回」と同じ形で実行し、その実行の `_selected` は**そのグループの ID だけ**、`_group` には**式の値**が入ります。
- **なぜ要るか**: `APPEND … SELECT` は 1 文 = 1 つの親なので、**複数の親（顧客など）に入れたいときはこの形だけ**です。
- **式の値が空のレコードは対象外**（グループに入れず、結果に「対象外 n 件」として出ます）。
- **グループの数の上限は 20**。超えたら実行前に断ります。1 グループの件数の上限は「まとめて 1 回」と同じ。
- 確認・書き込み上限は**起動 1 回の累計**（グループをまたいで数えます）。ログは 1 本（内訳に 成功 / 失敗 / 対象外）。
  失敗したときの続行・停止は `listOnError` に従います。

### 例（顧客ごとに、顧客マスタのテーブルへ明細を入れる）

```json
{ "type": "list", "selectionMode": "group", "groupFormula": "顧客コード",
  "params": [{ "name": "cust", "source": "formula", "formula": "" }] }
```

分ける式の値は `_group` に入るので、SQL では `@_group` を親の `WHERE` に使います（`params` に書くのは `_group` 以外の値だけ）。

```sql
-- @ksql dialect: 1
DECLARE @_selected = [];
DECLARE @_group = '';

UPDATE LAPP_顧客 SET 更新日時 = @NOW()
 WHERE 顧客コード = @_group
 APPLY 受注明細 (
   REMOVE ALL ROWS;
   APPEND (受注番号, 金額)
   SELECT 受注番号, 金額 FROM LAPP_受注 WHERE $id IN @_selected
 );
```

## 選ぶときの目安

| したいこと | 渡し方 |
|---|---|
| 選んだレコードを 1 件ずつ処理（印を付ける・それぞれの集計先を直す） | `loop` |
| 選んだレコードを 1 つの親のテーブルに入れる | `once` |
| 選んだレコードを顧客・部門ごとに分けて、それぞれの親に入れる | `group` |
| 1 回のクエリでまとめて集計したい（レコードごとの処理が不要） | `once` |
