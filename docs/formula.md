# 計算式の口（表示条件・実行条件・パラメーター・結果メッセージ）

計算式は同梱の計算式エンジン（計算式プラグイン `rex0220 formula` と同じもの）で評価します。**読み取り専用**で、値を書き換える経路はありません。

## 評価する 5 か所

| 設定 | いつ評価するか | 使えるもの |
|---|---|---|
| `showCond`（表示条件） | 画面を開いたとき（偽ならボタンを出さない） | レコードの値・`LOGIN_INFO`・`EV_INFO`・日付計算 |
| `execCond`（実行条件）・`execNgMessage` | 押したとき（偽なら実行せずメッセージ） | 同上 |
| `params[].formula`（パラメーター） | 押したとき（結果を SQL に注入） | 同上 |
| `inputs[].defaultFormula`（入力の既定値） | 入力ダイアログを出すとき | 同上 |
| `resultMessage`（結果メッセージ） | 実行の後 | 上記 + **`_result_*`** |
| `groupFormula`（分ける式） | 選んだ**レコードごと** | レコードの値（`selection`） |

- **項目はコードで書きます**（ラベルではない）。
- 式に **`//` から行末までのコメント**が書けます（評価の前に取り除かれます。コメントだけの式は空と同じ）。
- 空の式は「条件なし（真）」「パラメーターは空文字」として扱われます。

## 検査（どこまで見ているか）

**`kact_fields` で項目定義を取ってあるかで変わります**（返りの `summary.formulaCheck` に出ます）。

| `formulaCheck` | いつ | 見るもの |
|---|---|---|
| `syntax` | 項目定義の控えが無いとき | **式の構文だけ**（引用符 `"` と括弧の対応）。通らなければ `pFormulaSyntax`。引用符を忘れた素の文は `pFormulaQuote`（警告） |
| `fields` | `kact_fields` でそのアプリの項目定義を取った後 | **設定画面の保存と同じ検査**。構文に加えて**項目コードと関数名**も見る（無ければ `pFormulaField`）。レコード文脈の無いアクション（アプリ種別・まとめて 1 回・グループごと）で項目を参照した誤りもここで出る |

どちらでも**式そのものは findings に出しません**（口の名前だけ）。

- **項目コードは kintone から読んだものをそのまま使う**（表示名ではない）。`kact_fields` を使えない接続のときは、
  **利用者に項目コードを確かめる**（推測した項目コードは `syntax` の検査では誤りになりません）。
- 設定画面の保存は必ず項目定義を見て検査するので、**項目名を間違えていれば設定画面の保存で止まります**。

## 試し計算（`kact_try`）

検査（`kact_check`）は**誤りがあるか**しか見ません。**値がどうなるか**は `kact_try` で確かめます。
架空の値を当てて、実際の計算式エンジンに評価させます（**プラグイン本体の実行時と同じコード**。kintone には行きません）。

| 返り | 中身 |
|---|---|
| `value` / `valueType` | 評価した値と型 |
| `condition` | **表示条件・実行条件として見たときの真偽**（`"0"` / `"false"` / 空文字は偽。式が落ちても偽 = 安全側） |
| `param` | **SQL に注入される文字列**（`toParamValue`）。真偽値・配列は注入できないので `paramNg` が付く |
| `error` | 評価の失敗（項目コードの誤り・関数名の誤りはここに出る） |

```jsonc
// 「確認済（チェックボックス）に Y が入っていないレコードだけボタンを出す」を確かめる
{
  "app": 1001,                                  // kact_fields の控えを使う
  "data": { "確認済": [], "担当": "佐藤" },       // 架空の値（書かない項目は空）
  "formulas": [{ "formula": "NOT(IN(確認済, \"Y\"))", "as": "condition" }]
}
// → value: true / condition: true（出す）。"確認済": ["Y"] に変えると false（出さない）
```

- **1 回に 10 式まで**（探索を続けない）。式ごとに独立に評価します（1 つの誤りがほかを止めない）。
- `app` を省くと**項目の無い文脈**（種類 app・「まとめて 1 回」・「グループごと」と同じ）。項目を参照すると誤りになります。
- `result`（`{ "_result_updated": 4 }` など）を渡すと、**結果メッセージの文脈**（`_result_*` が使える）になります。
- `user`（`{ "code": "demo_user01" }`）を渡すと `LOGIN_INFO` が効きます。
- **値は架空のもの**を渡します（実在の個人情報・本番の値を入れない）。利用者のレコードでは値が変わることを添えて答えます。
- **これは模擬です。** 最後は利用者が実機でボタンを押して確かめます。
- 使うのは、**利用者が動きの確認を求めたとき**と、**資料に無い端の値（空・0・未選択）を断言するとき**です。
  関数の使い方をなぞるだけなら、計算式プラグインの資料で答えます。

**古い zip では使えません**（authoring API 版 4 以降が要ります）。`kact_status` の `apiVersion` で分かります。

## 使えない関数

**副作用のある関数は保存時に拒否します**: `FSET` 系・`BUTTON`・`DIALOG`・`CLIPBORD_WRITE`。
書き込みは SQL、画面はプラグインの UI が受け持ちます。
（`kact_try` は評価するだけなので、試すこと自体はできますが、**設定には保存できません**。）

## レコード文脈が無いとき

| 種類 | レコードの値 | `_record` |
|---|---|---|
| レコード（詳細・イベント） | 使える | 使える |
| 一覧の「1 件ずつ」 | 使える（処理中の 1 件） | 使える |
| 一覧の「まとめて 1 回」「グループごと」 | **使えない**（分ける式は例外） | **使えない** |
| アプリ | **使えない** | **使えない** |

レコード文脈が無い種類で、レコードの項目を参照する式を書くと**保存時エラー**です。
`LOGIN_INFO`・日付計算・入力項目の値は、どの種類でも使えます。

## 結果メッセージで使える変数

| 変数 | 値 |
|---|---|
| `_result_status` | `success` / `partial`（一部失敗・途中停止）/ `failed` / `cancelled`（断った・中止・上限超過）/ `timeout` |
| `_result_inserted` / `_result_updated` / `_result_deleted` | 実績の件数（`UPSERT` は分けられない分を updated に数える） |
| `_result_total` | 実績の合計 |
| `_result_planned` | 確認に出した予定の合計（実績と違うことがある） |
| `_result_ms` | 経過ミリ秒 |
| `_result_ok` / `_result_failed` / `_result_unprocessed` | 一覧のレコード数（成功 / 失敗 / 未処理）。一覧以外は 0 |

## よく使う式

| したいこと | 式 |
|---|---|
| 表示中のレコードの顧客コードをパラメーターに | `顧客コード` |
| 締め済みならボタンを出さない | `状態 <> "締め済み"` |
| 自分が担当のときだけ | `担当者コード = LOGIN_INFO("code")` |
| 金額が入っているときだけ | `金額 > 0` |
| **条件を 2 つ以上そろえる**（かつ） | `AND(顧客コード <> "", 処理状況 <> "締め済み")` |
| **どちらかでよい**（または） | `OR(処理状況 = "未処理", 処理状況 = "")` |
| **理由で文面を変える**（NG メッセージ） | `IF(処理状況 = "締め済み", "締め済みのため実行できません", "顧客コードを入れてください")` |
| 結果メッセージ | `"集計しました（" & _result_updated & " 件）"` |
| 追加の保存のときだけ実行 | `EV_INFO("cate") = "create"` |

- **実行条件は 1 つの口に 1 本**です。条件が複数あるときは `AND(…)` / `OR(…)` でまとめます
  （`&&` / `||` も使えますが、資料の例は `AND` / `OR` で書きます）。`NOT(…)` もあります。
- **メッセージも計算式です**。固定の文でも `"…"` で囲みます。**囲まないと項目コードとして読まれ**、
  `kact_check` は通っても**設定画面の保存で「項目が無い」と断られます**（引用符の抜けは構文としては正しいため）。
- 文字列の中に `"` を出したいときは `\"` と書きます（`"値は \"済\" です"`）。単引用符の文字列はありません。
- 全角の括弧（`（）`）は**文字列の中だけ**で使えます。式の括弧は半角です。
- 文字数は `LENGTH(…)`（`LEN` はありません）。空かどうかは `顧客コード <> ""` で足ります。

関数の一覧と詳しい使い方は、計算式プラグイン（`rex0220 formula`）の資料と同じです。
