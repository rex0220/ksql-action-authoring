# kact のリリース手順

**formula MCP の `docs/リリース手順.md` を元にした**（同じ手順。kact は tools と MCP が 1 つのリポジトリなので、npm の中核が無い）。

配るもの:

| 配布物 | 使う人 | 置き場所 |
| --- | --- | --- |
| Claude Desktop の拡張機能 `ksql-action-authoring-<版>.mcpb` | 一般の利用者 | GitHub のリリース |
| Claude Code のプラグイン `ksql-action`（marketplace `rex0220-ksql-action`） | Claude Code の利用者 | GitHub のリリースの zip を、`marketplace.json` から sha256 で固定して指す |

**npm には公開しない**（配布物に本体を束ねてあるので、中核のパッケージを要しない。formula / print-craft は中核をテンプレートの CLI が使うため npm に出している）。`npx` で使いたくなったら、そのときに決める。

外に出す操作（main への push、タグ、GitHub のリリース、`marketplace.json` の更新）は、**その都度 Takashi に確認する**。

## 1. 版を決める

- semver。0.x の間は、利用者に見える変更（ツールの入出力、設定項目、資料）で minor、直しで patch
- 版を書く場所（すべて同じ版に。`scripts/build.mjs` と `test/release.test.mjs` が食い違いで止める）:
  - `package.json` と `package-lock.json`: `npm version <版> --no-git-tag-version`
  - `compat.json` の `mcpVersion`
  - `.claude-plugin/plugin.json` の `version`（Claude Code は、この版が変わったときだけ新しい版を利用者に届ける）
  - README の確かめの表の、期待の版
- 本体（kSQL アクションプラグイン）の `AUTHORING_API_VERSION` が上がったら、`src/meta.ts` の `SUPPORTED_API_VERSIONS` に足して試験を流す（`compat.json` も合わせる）
- `CHANGELOG.md` に版の節を書く

## 2. まっさらな checkout から作って確かめる

作業中のフォルダーで作らない（入れてはいけないものが混ざらないように）。試験は隣の `ksql-action` の zip を使うので、`kintone-plugin/` の下に置く。

```sh
cd ~/Projects/kintone-plugin
git clone https://github.com/rex0220/ksql-action-authoring.git ksql-action-authoring-release
cd ksql-action-authoring-release
npm ci
npm run check
npm run build        # これを先に。MCP 層の試験は dist/mcp.mjs（資料を埋め込んだもの）を見るので、
                     # 省くと 16 件が skip される（2026-11-03 に気づいた）
npm test
npm run verify:mcpb
npm run verify:plugin   # CLAUDE=<claude の実行ファイル> で、展開したプラグインに claude plugin validate
"$CLAUDE" plugin validate . && "$CLAUDE" plugin test .   # プラグインの形と、フックの試験
```

- 成果物の名前をリリースの名前にする: `dist-mcpb/ksql-action.mcpb` → `ksql-action-authoring-<版>.mcpb`。プラグインの zip は `dist-plugin/ksql-action-authoring-plugin-<版>.zip`（名前はそのまま）
- sha256 を出す: `shasum -a 256 ksql-action-authoring-<版>.mcpb dist-plugin/ksql-action-authoring-plugin-<版>.zip`。**同じコミットから作れば同じ値**（埋め込む日時はコミットの日時。`.gitattributes` でどの機器でも LF で取り出す）
- 確かめが済んだら、このフォルダーは消してよい（消す前に成果物を退ける）

## 3. 手で確かめる（リリースの候補で）

- **Desktop**: 候補の `.mcpb` を入れ直し、Claude Desktop を起動し直して、README の Desktop の表を通す（準備の確かめ、`kact_status`、設定を 1 本作って保存、`kact_explain`、ログに秘密の値と SQL 本文が無いこと）
- **Claude Code**: README の Claude Code の表を通す。プラグインの zip を `claude --plugin-dir dist-plugin/ksql-action-authoring-plugin-<版>.zip` で読み込んで確かめる（marketplace の archive は https の URL しか受け付けないので、marketplace から入れる形は公開の後に 4-5 で）
- 取り込みは**試験用のアプリ**で（4377 など）。取り込みは全置換なので、今の設定が消えてよいことを確かめてから
- 結果を README の表に書く

## 4. 外に出す（各段で Takashi に確認）

1. **main に入れて push**（リリースのコミット）
2. **タグ**: `git tag -a v<版> -m "kact <版>"` → `git push origin v<版>`
3. **GitHub のリリース**:
   ```sh
   gh release create v<版> ksql-action-authoring-<版>.mcpb dist-plugin/ksql-action-authoring-plugin-<版>.zip \
     --title "kact <版>" --notes-file <ノートのファイル>
   ```
   ノートに書くもの: `CHANGELOG.md` の版の節、各ファイルの sha256、要る Claude Desktop と Claude Code の版、要る kSQL アクションプラグインの版（Ver.1 以降）、入れ方（Desktop はダブルクリック、Claude Code は `/plugin install ksql-action --marketplace rex0220/ksql-action-authoring`）
4. **marketplace を新しい版に**: `node scripts/write-marketplace.mjs dist-plugin/ksql-action-authoring-plugin-<版>.zip` → `claude plugin validate .` → main に push。**リリースにファイルを置いてから**書き換える（逆だと、入れられない時間ができる）
5. **公開したものを確かめる**: リリースからダウンロードしたファイルの sha256 が手元と同じか。Desktop で `.mcpb` を入れて版が新しいか（`kact_status`）。Claude Code で `/plugin marketplace update rex0220-ksql-action` → `/plugin install ksql-action@rex0220-ksql-action`、`/config` で zip と接続のファイルを設定できるか

## 6. まずかったとき

- **配布物に誤り**: `marketplace.json` を前の版の `url` と `sha256` に戻して push する（Claude Code）。GitHub のリリースは pre-release にするか、ファイルを外す（消すのは確認）。直した版を patch で出す
- **秘密の値や項目定義の控えが配布物に入った**: すぐにファイルを外し、該当するトークンを無効にする。Qiita などに上げた画像も同じ（記事から外しても、画像の URL は残る）
