# 設定ファイルの形（封筒・共通設定・アクション）

設定画面の［設定をダウンロード］［設定をアップロード］が読み書きする **1 ファイルの JSON**（封筒形式）です。
`kact_check` はこの形を受けて検査します。見るのは**設定画面の保存と同じ規則のうち、読み取りだけで分かる分**です。

**設定画面の［保存する］にしかできない検査が 2 つあります**（tools は kintone に書き込まないため。
`kact_check` が `ok` でも、取り込んだ設定画面で断られることがあります）:

| 設定画面だけの検査 | tools がする代わりのこと |
|---|---|
| **ログアプリへの試し書き**（項目の型が配布テンプレートと合うか・保存する人が読み書きできるか・`job_key` に重複禁止があるか） | `log-app-unverified` で「確かめていない」と言う（自アプリを指していないか・領域が控えと合っているかだけは見る） |
| **論理アプリの存在**（アプリ ID がそのドメインに実在するか） | 項目定義の控え（`kact_fields`）があるアプリだけ、**領域**（ゲストスペース）が自アプリと同じかを見る（`binding-area`） |

## 封筒（外側）

| キー | 値 | 備考 |
|---|---|---|
| `date` | `"2026-10-28 00:00"` | 書き出した日時（表示だけ） |
| `pluginName` | `"kSQL アクション"` | 表示だけ |
| `pluginID` | **`"rex0220 ksql action"`** | **これが合わないと取り込めない**（固定の識別子。kintone のプラグイン ID とは別） |
| `PluginVersion` | `"1"` | 書き出したプラグインの版 |
| `appId` / `appName` | `1001` / `"受注"` | 書き出した元のアプリ（表示だけ。別のアプリに取り込める） |

封筒の**同じ階層に設定本体のキーを並べます**（入れ子にしない）。

## 共通設定

| キー | 型 | 内容 |
|---|---|---|
| `configVersion` | `1` | 固定 |
| `bindings` | `[{ name, appId }]` | **論理アプリの対応表**。SQL では `LAPP_<name>` で参照する。自アプリも登録する。**自アプリと同じ領域のアプリだけ** |
| `logApp` | 下の表（任意） | 任意のログアプリ。**無ければ記録もロックもしない**（別ユーザーの二重実行は防げない） |
| `limits` | 下の表 | 制限 |
| `timezone` | `""` | as-of 関数（`@NOW()` / `@TODAY()`）の基準。空 = アプリの設定に従う |
| `panel` | `{ title, sections, views }` | **画面ごとの区分と出し方**（一覧のパネル・メニューと詳細画面。下の「パネル・区分（`panel`）」） |
| `progressStyle` | `"dialog"` / `"spinner"` | イベント実行中の見せ方（既定 `dialog`） |
| `messages` | `[{ code, text, text_ja?, text_en?, text_zh? }]`（任意） | **共通の文**（下の「共通の文（`messages`）」）。**ツールからは足せません** |
| `actions` | `[ActionDef]` | アクションの列。**並びがボタンを出す順**（同じイベントの実行順も同じ） |
| `pluginComment` / `pluginDescription` | 文字列（任意） | 設定する人の覚え書き。利用者の画面には出ない |

## 共通の文（`messages`）と多言語

### 共通の文（`messages`）

画面に出す文を共通設定にまとめて持ち、**同じ文を複数のアクションで使い回す**ための設定です
（多言語のためだけではありません。1 言語でも「直すのは 1 か所」で役に立ちます）。

```jsonc
"messages": [
  { "code": "m_no_amount", "text": "金額が空です", "text_en": "Amount is empty", "text_zh": "金额为空" },
  { "code": "m_done", "text": "{n} 件を書き込みました", "text_en": "Wrote {n} records" }
]
```

**記号は書く場所で決まります。** 表に持つのは**記号なしの名前**です。

| 書く場所 | 形 |
|---|---|
| 計算式 | **`$m_done`**（擬似項目。`$id` / `$result_*` と同じ族） |
| SQL | **`@m_done`**（変数。`DECLARE @m_done = '';` が要る） |
| 設定の `code` | **`m_done`**（記号なし） |

| 決め | 中身 |
|---|---|
| コード | `m_` で始まり、後ろは `[a-z0-9_]`（**小文字だけ**）、64 字まで、一意 |
| 既定の文（`text`） | **必須**（各言語が空のときに落ちる先） |
| 使える式の口 | **`execNgMessage` / `resultMessage` / `inputs[].optionLabelsFormula` の 3 つだけ**。ほかの口に `$m_…` を書くと `message:slot` の error |
| SQL | `ASSERT` と `EXIT SUCCESS IF` のメッセージだけ。`m_` でない変数をメッセージに書くと error（表示は何も出ないため） |
| 値の差し込み | 文に **`{@名前}`** と書くと、`ASSERT` / `EXIT` で出すときにその SQL で `DECLARE` した変数の値が入る（例「{@year} 年の受注が多すぎます」）。`SET` の値・配列・共通の文・`DECLARE` していない名前は error（`pMessagePlaceholder`。4 列とも見る）。計算式の口では置き換わらない（`REPLACE` を使う。`sql` の章） |
| 上限 | 50 件 / 1 つの文は 200 字（4 列とも同じ） |
| **`m_` は名前としても予約** | パラメーター（`params[].name`）と入力項目（`inputs[].name`）に `m_` 始まりの名前は付けられません（`param:reserved-message` / `input:reserved-message` の error。大文字小文字は区別しません） |

> **【大事】`messages` はツールからは足せません**（`kact_save_config` が `messages-not-writable` で**断ります**）。
> `kact_save_config` / `kact_update_action` は `messages` を作らないので、
> **利用者に設定画面のツールバーの［メッセージ］で足してもらってください**。
> 今ある文のコードは **`kact_actions` の返りの `messages`** で分かります（文そのものは返りません）。
> **無いコードを式に書くと `kact_check` が error にします。**

```
// 計算式の例（件数を埋める）
REPLACE($m_done, "{n}", $result_total)
```

```sql
-- SQL の例（エンジン 3.90.0 以降）
DECLARE @m_no_stock = '';
ASSERT (SELECT COUNT(*) FROM LAPP_在庫 WHERE 残数 < 0) = 0, @m_no_stock;
```

### 多言語（日・英・中）

**利用者の言語**（`ja` / `en` / `zh`。それ以外は `en`）で、設定した文字を出し分けます。
**その言語が空（空白だけも空）なら既定のキー**に落ちます（英語・日本語には落ちません）。

| 設定 | 足すキー |
|---|---|
| `actions[].name` / `actions[].description` | `name_ja` / `name_en` / `name_zh`、`description_*` |
| `panel.title` | `title_*` |
| `panel.sections[].name` | `name_*`（**表示名だけ**。`name` はキーのまま） |
| `actions[].inputs[].label` | `label_*` |
| `actions[].inputs[].options[]` | `options_ja` / `_en` / `_zh`（**ラベルの配列**。値は `options` のまま） |

- すべて**任意**で、**空の言語はキーごと書かない**でください（設定が無駄に膨らみます）。
- **区分の名称はキー**です。`name_*` を変えても `panelSection` や `panel.views[].sections` の参照は動きません。
- **ログに残る名前は翻訳されません**（`name` のまま）。
- 選択肢のラベルは**要素数が違っても保存できます**（足りない分は値がそのまま出ます）。

### `logApp`（任意）

`logApp` を**書くなら、`appId`・`profile`・`guestSpaceId` の 3 つは必ず入れます**（1 つでも欠けると
`$.logApp.guestSpaceId: required` のように `parse-failed` で保存できません。ここは `kact_save_config` が
既定値で埋めない数少ないところです）。`logApp` そのものを省くのはかまいません（記録もロックもしない）。

| キー | 既定 | 内容 |
|---|---|---|
| `appId` | **必須** | ログアプリのアプリ ID。**自アプリは選べません** |
| `profile` | **必須**（空文字でよい） | 実行環境名（20 字まで）。ロックのキーの先頭にも使う。空なら `kact<アプリ ID>`。**1 つのログアプリを複数のアプリで使っても、アプリごとに分かれます**（2 つのアプリでロックを共有したいときだけ同じ名前にする） |
| `guestSpaceId` | **必須**（通常領域なら `0`） | ログアプリのゲストスペース ID。設定画面は**ダイアログでログアプリを選び直したときだけ**自動で入れるので、**取り込んだ値はそのまま残ります**。通常領域のログアプリなら `0`、ゲストスペースのログアプリなら**その ID を利用者に聞いて**書きます（間違うとログもロックも書けません） |
| `viewId` | `0` | ログ一覧へのリンクで開く一覧 ID（0 = ログアプリの既定の一覧）。`kact_views` で読める |
| `panelLog` | `false` | 一覧パネルに「最近の実行」を出す |
| `panelLogOpen` | `false` | その枠を既定で開く（**開いている間だけ照会する**ので、閉じていれば API を使わない） |
| `panelLogCount` | 20 | 取る件数（1〜50） |
| `panelLogRefreshMin` | 10 | 自動更新の間隔（分。**0 = しない**。1〜1440） |

`panelLog*` は見た目の好みなので、**利用者に頼まれないかぎり触らなくてかまいません**。

### `limits`

| キー | 既定 | 内容 |
|---|---|---|
| `readMax` | 10000 | 読み取りの上限件数。**1 回の読み取りごと**（合計ではない。一時テーブルを作る文の元の読み取りにも効く） |
| `tempTableMax` / `tempTotalMax` | 10000 / 20000 | 一時テーブルの行数。`tempTableMax` は**出来た表 1 つ**の行数（JOIN・UNION で増えた行も数える）、`tempTotalMax` は残っている表の合計 |
| `timeoutMin` | 60 | 実行タイムアウト（分）。**1 コンテキストごとに計り直します**（一覧は 1 レコード・1 グループ、ループは 1 回）。起動 1 回の合計ではないので、**10 回のループは「制限時間 × 10」まで動けます**（`limits` の「数える単位」） |
| `apiTimeoutSec` | 60 | API 通信のタイムアウト（秒） |
| `listBulkMax` | 300 | 一覧の選択の上限（「まとめて 1 回」は min(これ, 200)） |
| `applySubtableMax` | 500 | **APPLY で変わる子行の上限**（1 文。`REMOVE ALL ROWS` で消える既存行も数える） |
| `loopMax` | 100 | **ループの回数**（1 つの対象あたり。1〜100。`loop`） |
| `runMax` | 1000 | **ループの回数の合計**（起動 1 回。1〜10000） |

**`kact_save_config` は足りないキーを本体の既定値で埋めます**（`configVersion` / `limits` / アクションの各キー）。変えるところだけ渡してください。

## アクション（`actions` の 1 要素）

```json
{
  "enabled": true,
  "code": "mark",
  "name": "印を付ける",
  "description": "",
  "type": "record",
  "onList": false,
  "placements": ["detail_menu"],
  "panelSection": "",
  "showCond": "",
  "execCond": "",
  "execNgMessage": "",
  "params": [{ "name": "cust", "source": "formula", "formula": "顧客コード" }],
  "inputs": [],
  "sql": "-- @ksql dialect: 1\nDECLARE @cust = '';\nUPDATE LAPP_受注 SET 処理状況 = '済' WHERE 顧客コード = @cust;",
  "staticInsertRows": 0,
  "confirm": true,
  "writeLimit": 0,
  "refreshPrompt": "auto",
  "allowed": [],
  "allowAll": true,
  "resultMessage": "",
  "listOnError": "continue",
  "selectionMode": "loop",
  "groupFormula": "",
  "loop": "",
  "loopOnError": "stop",
  "perRecordLock": false,
  "prevRecord": false
}
```

| キー | 値 | 備考 |
|---|---|---|
| `enabled` | 真偽 | 無効なら起動口を出さずイベントにも反応しない。**無効の行は SQL を検査しない**（下書き） |
| `code` | `[A-Za-z_][A-Za-z0-9_]*`、32 字まで | 大文字小文字を無視して一意。ロックキーとログに使う。**あとで変えない** |
| `name` / `description` | 文字列 | ボタン・パネルに出す。**`name` は必須**（空では保存できない。100 字まで。2026-11-05 から検査する）。`description` は 500 字まで |
| `type` | `"record"` / `"app"` | レコード 1 件に実行 / レコードに依らない処理（**2026-10-31 に 3 つから 2 つになった**。旧 `"list"` は `"record"` ＋ `onList: true` に読み替わる） |
| `onList` | 真偽 | **一覧画面でも使う**（選んだレコードに実行）。`type: "record"` のときだけ |
| `placements` | 下の表 | 詳細画面の出し場所（複数可）とイベント。**一覧画面の出し方はここでは決めない** |
| `panelSection` | 文字列 | **区分の名称**（空 = 区分なし）。`panel.sections` に**有効な区分として定義した名前だけ**（定義に無いと注意 `wUnknownSection`。保存はできるが**どの一覧にも出ません**）。一覧のパネル・メニューと詳細画面の両方に効く |
| `showCond` | 計算式 | 偽ならボタンを出さない（イベント起動には効かない） |
| `execCond` / `execNgMessage` | 計算式 | 偽なら実行せずメッセージ |
| `params` | `[{ name, source, formula }]` | SQL の `DECLARE` と**過不足なく 1 対 1**（下の「パラメーターと入力項目」） |
| `inputs` | `[{ name, label, type, required, defaultFormula, options, optionsFormula, optionLabelsFormula, minValue, maxValue, minLength, maxLength }]` | 実行時に聞く値。`type` は `text` / `number` / `date` / `datetime` / `select` / `relative_date`。**イベント起動には持てない**（`enabled: false` にした行は数えないので、無効にすればイベント起動にできる。下の「パラメーターと入力項目」） |
| `sql` | Flow dialect 1 | 1 本 20,000 字・20 文まで（`sql`） |
| `staticInsertRows` | 整数 | 素の `INSERT … VALUES` の行数。**保存のときにプラグインが数え直して上書きする**ので、AI は書かなくてよい |
| `confirm` | 真偽 | 既定 `true`（件数の確認）。`false` にすると `writeLimit` が**必須** |
| `writeLimit` | 整数（0 = 無し） | 起動 1 回で書いてよい合計件数 |
| `allowed` | `[{ type, code, name? }]` | `type` は `USER` / `GROUP` / `ORGANIZATION`。空 = 全員。**誤操作防止**で、セキュリティ境界ではない |
| `allowAll` | 真偽 | `true` なら `allowed` を見ずに全員（`allowed` は消さずに残す）。既定 `true` |
| `refreshPrompt` | `"auto"` / `"always"` / `"never"` | 完了のダイアログに［この画面を更新］を出すか。`auto` = このアプリに書いたときだけ |
| `resultMessage` | 計算式 | `$result_*` が使える（`formula`）。空 = 既定の文 |
| `listOnError` | `"continue"` / `"stop"` | 一覧の 1 件ずつのときだけ効く |
| `eventLog` | `"failed"` / `"all"` / `"none"` | **イベント起動のときだけ**ログアプリに何を残すか。既定は `"failed"`（失敗だけ）。イベントは何度も起きるので、`"all"` にするとログが膨らみます（1 日 100 件の更新で年に数万件）。**ボタンと一覧の一括には効きません**（記録が二重実行を止める仕組みなので省けない） |
| `selectionMode` | `"loop"` / `"once"` / `"group"` | 一覧で選んだレコードの渡し方（`selection`）。**`onList: true` のときだけ効く** |
| `groupFormula` | 計算式 | `selectionMode: "group"` の**分ける式** |
| `loop` | 計算式 | **同じ SQL を回数ぶん流す**（空 = ループなし = 1 回）。非負の整数 `N` なら `N` 回、配列ならその要素（`loop`）。**使うなら `writeLimit` が必須** |
| `loopOnError` | `"stop"` / `"continue"` | ループの回が失敗したとき。既定は `"stop"`（残りの回を流さない） |
| `perRecordLock` | 真偽 | ログアプリ指定時のみ。ロックキーにレコード ID を足す |
| `prevRecord` | 真偽 | 起動に `event_edit` があるときだけ。集計先が変わったときに**前の集計先も**直す |

### `placements`

| 値 | 場所 | 使える種類 |
|---|---|---|
| `detail_menu` | 詳細画面のヘッダー | record |
| `event_create` | 保存後（追加） | record のみ |
| `event_edit` | 保存後（編集。一覧のインライン編集を含む） | record のみ |
| `event_status` | ステータス変更（遷移が確定した後の詳細画面で実行） | record のみ |
| `event_delete` | **削除したあと**（削除する前に控えを取り、削除が成功してから実行） | record のみ |
| `check_create` | **保存前の検査（追加）**。止まったら保存を取り消す（`sql` の「保存前の検査」） | record のみ |
| `check_edit` | **保存前の検査（編集。一覧のインライン編集を含む）** | record のみ |
| `check_delete` | **削除前の検査** | record のみ |

**保存前の検査（`check_*`）の行は、ほかの起動と混ぜません**（`detail_menu`・`event_*`・`onList: true` と同じ行にすると `check:mixed` の error）。
書く文は置けず（`pCheckWrite`）、入力項目・ループも持てません。`confirm` と `writeLimit` は見ない（書かないので数える件数が無い）ので、
`confirm: false`・`writeLimit: 0` のままでかまいません。**「実行を許す人」は見ず、全員に効きます**（例外は `execCond` に `LOGIN_INFO` で書く）。

**一覧画面に出す道**（2026-10-31 に `index_menu` / `index_panel` をやめた）: アクション側は `onList`（種類 record）か
種類 `app` で「一覧画面に出る」ことだけを決め、**どの一覧にどう出すか（パネル / メニュー / 出さない）は共通設定の `panel`** で決めます。

**種類 `app` の `placements` は空（`[]`）です。** 詳細画面には出ないので `detail_menu` を入れると
`action[n]:app:placement` で保存できません（イベントも種類 record だけなので、種類 `app` に入れられる値はありません）。
種類 `app` のアクションは **`panel` で一覧に出さないとどこにも出ない**ので、
区分（`sections` に名前）か、区分なしのボタンとして必ず `panel.views` に載せます。

**詳細画面に出るかどうかは `placements` の `detail_menu` だけで決まります**
（一覧の行で「出さない」にしても、詳細画面のボタンは出たままです）。
**出し方**（ボタンかメニューか）は、`panel.views` の**先頭の「詳細画面」の行**で決めます（下の「詳細画面の行」）。
**モバイルはその行を見ず、区分を付けたものは常にメニューにまとまります。**
区分（`panelSection`）はアクションに 1 つで、**一覧パネルの節とモバイルの詳細メニューの両方**に効きます
（別々には付けられません。一覧に出さない区分を詳細用に作るのはかまいません）。

### パネル・区分（`panel`）

設定画面のツールバーでは **［パネル・区分］** という名前のダイアログです（2026-11-06 までは［一覧パネル］）。
キーの名前は `panel` のままですが、**一覧画面のパネルだけでなく詳細画面の出し方も**ここで決めます。

```json
{
  "title": "",
  "sectionColumns": 1,
  "buttonWidth": 200,
  "buttonLogLink": false,
  "sections": [{ "enabled": true, "name": "受注", "color": "blue", "tone": "soft", "collapsed": false }],
  "views": [{ "viewId": "*", "sections": ["受注"], "menus": [], "open": false }]
}
```

| キー | 値 | 備考 |
|---|---|---|
| `title` | 文字列 | パネルの帯の名前（空 = プラグイン名） |
| `sectionColumns` | 1〜6（省略 = 1） | **1 行に並べる区分の数**。1 = 縦に積む（従来）。指定するのは**最大の列数**で、ボタンの幅が入らなくなったら自動で減る。モバイルは常に 1 列 |
| `buttonWidth` | 120〜400（省略 = 200） | **ボタンの幅**（px。カードの最小幅）。列がこれより広ければボタンは列いっぱいに伸びる。**区分を 4 つ以上横に並べるなら下げる**（下げないとボタンの名前が切れる）。モバイルは常に幅いっぱいで効かない |
| `buttonLogLink` | 真偽（省略 = `false`） | ボタンにログ一覧へのリンクを出すか。**既定は出さない**。出さなくても、帯と区分の見出しのリンクからログ一覧へ行ける |
| `sections` | `[{ enabled, name, color, tone, collapsed }]` | **区分の定義**。`name` がキー（アクションの `panelSection` と突き合わせる）。`color` は 8 色 ＋ `""`、`tone` は `"soft"` / `"vivid"`、`collapsed` は既定で畳むか。**無効（`enabled: false`）の区分は定義していないのと同じ** |
| `views` | `[{ viewId, sections, menus, open, enabled? }]` | **一覧ごとの出し方**。`viewId` が `"detail"` の行は**詳細画面**（必ず先頭。下）、`"*"` の行は「ほかの一覧すべて」。`sections` = パネルに出す区分、`menus` = メニューに出す区分（メニュー名は区分名。区分なしはボタンを直接並べる）、`open` = パネルを開いて出すか、`enabled` = この行の指定を効かせるか（省略 = 効かせる） |

> **区分なしは `""` という名前で載せます。** `sections` と `menus` に並べるのは**区分の名前**で、
> 区分を付けていないアクション（`panelSection: ""`）は **`""`** が自分の名前です。
> だから「区分なしのボタンを一覧パネルに出す」設定は、こう書きます:
> `{ "viewId": "*", "sections": [""], "menus": [], "open": false }`
>
> **`panel` を省くと「既定」にはなりません（必ず書いてください）。** 取り込みのときに走る移行は、
> `panel.views` を**旧い起動口**（2026-10-31 まであった `index_panel` / `index_menu`）から起こすので、
> 今の形のアクションしか無い設定では **`"sections": []` の行**になり、**ボタンはどこにも出ません**。
> 一覧に出すアクションがあるなら、`panel.views` を省略せずに書きます。
>
> **`"sections": []` は「この一覧には何も出さない」という意味です。** 空の配列は「ぜんぶ出す」ではありません。
> 区分を付けていないアクションしか無いのに `[]` と書くと、**ボタンはどこにも出ません**
> （種類 `app` は詳細画面に出ないので、本当にどこからも使えなくなります）。
> 名前付きの区分だけを並べた `"sections": ["受注"]` も同じで、`panelSection: ""` のアクションは出ません。
> `kact_check` はこの形に注意（`wNowhereShown`）を出します。

#### 詳細画面の行（`viewId: "detail"`）

**PC の詳細画面でボタンを区分ごとのメニューにまとめるか**を決めます（2026-11-06 に足しました）。

```jsonc
// 請求の区分だけメニューにまとめ、ほかはボタンのまま
{ "viewId": "detail", "sections": [], "menus": ["請求"], "open": false }
```

- 使うのは **`menus` だけ**です。詳細画面に**パネルは無い**ので `sections` と `open` は空のままにします。
- **`menus` に入れた区分がメニュー**に、入れていない区分は**ボタンのまま**並びます。
- **区分なし（`""`）はメニューにできません**（名前が無いので畳めません）。`menus` に `""` を入れても無視されます。
- **行が無ければ全部ボタン**です（2026-11-06 より前の設定と同じ）。**新しく作るときも、まとめたい区分が無ければ行は要りません。**
- **`enabled: false` にすると詳細画面にアクションを 1 つも出しません**（PC もモバイルも）。
  区分ごとの指定は残るので、**一時的に隠して後で戻せます**。
- **詳細画面に出すかどうかは、この行では決まりません。** アクションの `placements` に `detail_menu` があるかだけで決まります。
- **モバイルは `menus` を見ません**（横幅が狭いので、区分を付けたものは常にメニューにまとまります）。`enabled: false` はモバイルでも効きます。

**`"*"` の行だけで済むなら、一覧ごとの行は足しません。** 一覧ごとの行は「**この一覧だけ別扱い**」のためにあります
（例: ある一覧ではパネルではなくメニューに出す、ある一覧では出さない）。

一覧 ID は **`kact_views`** で読めます（番号は推測しない）。**どの一覧を別扱いにするかは利用者に確かめます**。

> **「(すべて)」は API に返りません。** kintone の作りつけの「(すべて)」は `views.json` に含まれないので、
> `kact_views` が `viewId: "20"` の行を**末尾に足して**返します（本体の設定画面と同じ作り）。
> 「(すべて)」でだけ出し方を変えたいときは、この `"20"` を書きます。
> また、**同じ名前の一覧があると kintone は一覧の設定を返しません**（REST の制限）。

ある一覧でだけ出さない例（既定はパネルに出し、一覧 `1102` では出さない）:

```json
"views": [
  { "viewId": "*",    "sections": ["受注"], "menus": [], "open": false },
  { "viewId": "1102", "sections": [],       "menus": [], "open": false }
]
```

区分の名前を変えるときは、アクションの `panelSection` も一緒に変えます。

> **今ある設定の `panel` を直すときは、先に `kact_pull`** で今の設定を作業フォルダーに取ってから直します。
> **`panel` の中身を返すツールはありません**（`kact_actions` が返すのはアクションごとの `panelSection` だけで、
> 区分の定義や 画面 × 区分 の表は出ません）。`kact_save_config` は**設定全体のファイル**を書くので、
> `panel` を省くと**今ある区分と 画面 × 区分 の表が消えます**（上の「区分なしは `""`」も読んでください。
> 省略は「既定に戻る」ではなく、**どこにも出ない行になります**）。
> 今の区分や一覧ごとの出し方が分からないときは、**推測せずに利用者に確かめてください**
> （設定画面の［パネル・区分］を開いてもらえば見えます）。

**区分を横に並べるときの目安**（`sectionColumns` と `buttonWidth` の組み合わせ）:

| 区分を横に | ボタンの幅 |
|---|---|
| 1（既定） | 200 のまま |
| 2〜3 | 200 のままで足りる |
| 4 以上 | **140〜160 に下げる**（1360px の画面で 6 列にすると、区分 1 つは 200px ほどしか残らない） |

#### 「パネル」と「メニュー」の使い分け

同じ区分を `sections`（パネル）にも `menus`（メニュー）にも書けますが、**出るものが違います**。

| | パネル（`sections`） | メニュー（`menus`） |
|---|---|---|
| 場所 | 一覧の上の**折りたたみパネル**（ヘッダースペースの先頭） | kintone の**ヘッダーメニュー**（ツールバーの並び） |
| 出るもの | ボタン名 ＋ **説明**（2 行まで。全文は吹き出し）、**区分の色**、ボタンごとの**ログ一覧リンク**（`buttonLogLink`） | **ボタン名だけ**（説明・色・ログリンクは出ません） |
| 区分の見え方 | 区分ごとの**節**。見出しに区分名と件数が出て、**節ごとに畳めます** | 区分ごとに**メニューが 1 つ**（メニュー名 = 区分名）。**区分なしはボタンを直接**並べます |
| 場所 | 縦に場所を取ります（畳める。開閉は**一覧ごとに覚えます**） | ほとんど取りません |
| ほかに付くもの | 帯の［画面を更新］と「最近の実行」 | 無し |

- **レコードを選んでから押すもの**（`onList: true` の一括処理）は**ボタン・メニューを先に考えます**。
  ツールバーに出るので**表を押し下げません**。選ぶには行が見えている必要があるためです。
  代わりに説明が出ないので、**名前だけで何をするか分かる**ようにします（「処理」ではなく「選択分を処理済へ」）。
- **それ以外で迷ったらパネル**にします。**説明が出る**ので、現場の人が「このボタンは何をするのか」をその場で読めます。
  説明（`description`）を書いておくのが前提です。月次集計や締めのように**たまにしか押さない**ものはこちら。
- **出す場所は「押せる人」の設定ではありません。** ある一覧から外しても、詳細画面やほかの一覧には出たままです。
  押せる人を絞るのは `allowed` / `allowAll` と `execCond` で、それも**誤操作防止**です（`limits` の「権限」）。
- **両方に書くとボタンが 2 か所に出ます**（同じアクションが二重に並ぶ）。ふつうはどちらか一方にします。
- **一覧ごとに変えられます**。「ふだんはパネル、アクション専用の一覧だけメニュー」のような分け方ができます。
- モバイルの**詳細画面**では、区分を付けたアクションは**区分ごとのメニュー**にまとまります（横幅が狭いため。
  PC の詳細画面は区分を見ずにボタンを並べます）。区分名は**モバイルでメニュー名として出る**ことを見越して付けます。

**イベント起動の決まり**: 確認なし（`confirm: false`）＋ `writeLimit` 必須 ＋ `inputs` なし ＋ `showCond` は効かない。
イベントは**ブラウザーの操作だけ**で動きます（REST API・CSV 読み込みでは動かない）。
`event_delete` も画面から消したときだけ動きます。**削除は非推奨**で、アプリに「削除フラグ」を持たせて集計から外す形を勧めます。

## パラメーターと入力項目

SQL の `DECLARE` 1 本につき **`params` の行が 1 つ**要ります（予約名 `_record` / `_selected` / `_group` などは除く。`sql`）。
値の出どころが `params[].source` で、**実行時に聞く値（`"input"`）のときは `inputs` にも同じ名前の行**が要ります
（**`params` だけ・`inputs` だけでは足りません**。`inputs` だけだと `pParamMissing`、`params` だけだと `pInputMissing`）。

```jsonc
// DECLARE @cust（レコードの値）と DECLARE @memo（実行時に聞く値）の 2 本があるとき
"params": [
  { "name": "cust", "source": "formula", "formula": "顧客コード" },  // 計算式で決める
  { "name": "memo", "source": "input" }                              // 実行時に聞く → inputs にも要る
],
"inputs": [
  { "name": "memo", "label": "処理メモ", "required": true }
]
```

- `source: "input"` の行に `formula` は要りません（空で埋まります）。
- **`params` と `inputs` の `name` は同じ規則**です（2026-11-05 にプラグイン側で入力項目にも検査が入りました）。
  半角英字か `_` で始まり、半角英数字と `_` だけ、64 字まで。`_` 始まりは予約です。
  **大文字小文字を区別せずに重複できません**（実行時は小文字にしてキーにするので、`year` と `YEAR` は同じ 1 つと見ます）。
- `params` / `inputs` の行には **`enabled`**（真偽。既定 `true`）があります。`false` にすると**その行を一時的に使いません**
  （パラメーターは注入せず、入力項目は聞きません）。どちらも値が無いので **SQL の `DECLARE` の既定値**が使われます。
  `DECLARE` との突き合わせは今までどおりなので、**SQL は直さなくてかまいません**。
  **無効の行は計算式を検査しません**（`kact_check` も設定画面も）。作りかけの式を置いたまま、ほかを先に進められます。
- `inputs` の `label` / `type` / `required` / `defaultFormula` / `options` は**書かなければ既定で埋まります**
  （`label` は名前、`type` は `text`、`required` は `false`、`options` は `[]`）。
- `options` を書くのは `type` が **`select`** か **`relative_date`** のときだけです。どちらも**選択肢**として出るので、
  空のままだと利用者は何も選べません（`relative_date` では、許す日付関数のトークンを並べます）。
- `type: "relative_date"` の入力項目と対になる `DECLARE` は、`RELATIVE_DATE` 注釈つきで書きます（`sql`）。

### 選択肢を計算式で出す（`optionsFormula` / `optionLabelsFormula`）

`type: "select"` のとき、候補を**計算式**で出せます。**`optionsFormula` が空でなければ `options` は使いません。**

| キー | 中身 |
|---|---|
| `optionsFormula` | 選択肢の**値**（SQL に注入されるほう）。配列、または 1 つの文字列・数値を返す式 |
| `optionLabelsFormula` | 選択肢の**ラベル**（画面に出るだけ）。**値と同じ数・同じ順**で返す式。空なら値をそのまま出す。**これだけ書いて `optionsFormula` が空だと保存できません**（ラベルが黙って無視されるため） |

```jsonc
// 前月・当月・翌月から請求月（YYYY-MM）を選ばせる
{ "name": "month", "label": "請求月", "type": "select", "required": true,
  "optionsFormula": "ARRAY(DATE_ADD(\"TODAY\", -1, \"month\", \"YYYY-MM\"), DATE_FORMAT(\"TODAY\", \"YYYY-MM\"), DATE_ADD(\"TODAY\", 1, \"month\", \"YYYY-MM\"))" }

// 担当者を「表示名で選ばせて、ログイン名を注入する」
{ "name": "user", "label": "担当者", "type": "select",
  "optionsFormula": "SEL_CODE(担当者, \"array\")",
  "optionLabelsFormula": "SEL_NAME(担当者, \"array\")" }
```

- 空の値と重複は落とします（`toParamValue` を通した文字列で見ます）。**落とすときはラベルも同じ添字で落ちます。**
- ラベルの数が値の数と違う、候補が 1 つも残らない、配列でも 1 つの値でもない、
  要素やラベルが文字列・数値でない（`null` / 真偽 / 入れ子の配列）→ **実行前エラー**（実行しません）。
- **`type` が `select` のときだけ**効きます。ほかの型に残っていても無視され、検査もしません。
- 上限は 100 件（固定の `options` と同じ）。
- **`relative_date` には書けません**（許す日付関数のトークンを保存時に確かめるため、`options` で並べます）。

#### レコードの項目を使えるのは詳細画面のボタンだけ

入力は**起動 1 回につき 1 回**しか聞かないので、一覧からの実行では式を当てるレコードが決まりません。
`defaultFormula` / `optionsFormula` / `optionLabelsFormula` でレコードの項目を使えるのは
**`type: "record"` かつ `onList: false`** のアクションだけで、そうでないのに項目を書くと**保存できません**。
日付計算（`TODAY` / `DATE_ADD` / `DATE_FORMAT`）やログイン情報は、どの起動でも使えます。

### 入力できる値を絞る（`minValue` / `maxValue` / `minLength` / `maxLength`）

**キーを書かなければ制限なし**です（`0` は「制限なし」ではなく「下限 0」の意味になります）。

| 型 | キー | 中身 |
|---|---|---|
| `number` | `minValue` / `maxValue` | **値**の範囲 |
| `text` | `minLength` / `maxLength` | **文字数**（0 以上の整数）。**コードポイントで数えます**（`value.length` ではないので、多くの絵文字は 1 文字） |
| `date` / `datetime` / `select` / `relative_date` | — | **範囲は指定できません**（書いても実行時に無視されます） |

- **効くのは型に合うキーだけ**です（`options` と同じ）。`text` の行に残った `minValue` は実行時に見ません。
  **ただし「最小 > 最大」の検査は型に関係なく効きます。** 型を `number` から `text` に変えたときに
  `minValue` / `maxValue` が逆のまま残っていると、使われないのに**保存で止まります**。型を変えたら要らないキーは消してください。
- 範囲から外れたまま実行しようとすると、**理由を出して止まります**（書き込みは起きません）。
- **数値の欄に数でない文字**（`1e` など）が入っているときも実行できません。
  このとき欄の値は空になるので、「任意の数値に `abc`」が**未入力のまま静かに通る**ことはありません。
- 空のまま実行したときは、`required: true` なら止まり、`required: false` なら**注入しません**
  （SQL の `DECLARE` の既定値が使われます）。

### キーの配列（`source: "keys"`）

**その起動で関係するレコードすべて**に式を当て、重複と空を落として**配列**で渡します。
キーの項目（顧客コードなど）を直したとき・レコードを消したときに、**新旧のキーを 1 回の実行でまとめて**渡すための源泉です。

| 起動 | 配列の中身 |
|---|---|
| ボタン・一覧の 1 件ずつ | `[そのレコード]` |
| 一覧の「まとめて 1 回」「グループごと」 | 選んだレコード全部 |
| `event_create` | `[新しい値]` |
| `event_edit` | `[変更後, 変更前]`（控えがあるとき。同じなら 1 件） |
| `event_delete` | `[消したレコードの値]` |

```jsonc
"params": [{ "name": "keys", "source": "keys", "formula": "顧客コード" }]
```

**`formula` は必ず書きます**（空だと `param:keys-formula` の error。空の式では何も渡りません）。

```sql
DECLARE @keys = [];   -- 配列で宣言する（`pKeysNotArray`）
DECLARE @now = '';    -- 集計日時は計算式のパラメーターで渡す（DATE_FORMAT(NOW(), "YYYY-MM-DDTHH:mm:ssZ")）

-- 今の集計を「0 の行」として足してから集計する（消す文も 0 にする文も無いので、途中で失敗しても壊れない）
CREATE TEMP TABLE #t AS
SELECT 顧客コード, COUNT(*) AS 件数, SUM(金額) AS 売上
  FROM LAPP_受注 WHERE 顧客コード IN @keys GROUP BY 顧客コード
UNION ALL
SELECT 顧客コード, 0 AS 件数, 0 AS 売上
  FROM LAPP_集計 WHERE 顧客コード IN @keys;

UPSERT INTO LAPP_集計 (顧客コード, 件数, 売上, 集計日時)
SELECT 顧客コード, SUM(件数) AS 件数, SUM(売上) AS 売上, @now AS 集計日時
  FROM #t GROUP BY 顧客コード
ON DUPLICATE (顧客コード);

-- 行を残したくないときは、集計のあとで 0 の行だけ消す
DELETE FROM LAPP_集計 WHERE 顧客コード IN @keys AND 件数 = 0;
```

- **先に `UPDATE … SET 件数 = 0` で埋める形は勧めません**（書き込みが 2 倍、0 にしたあとで失敗すると 0 のまま残る）。
- **集計日時は `@NOW()` でも、計算式のパラメーターでも書けます。** `@NOW()` は **`SELECT` の列にも書ける** as-of 関数です（`sql` の「as-of 関数」。起動 1 回につき 1 回だけ決まるので、全レコードで同じ値になります）。`patterns` の全体再計算は `@NOW() AS 集計日時` と直接書いていて、こちらのほうがパラメーターが 1 本減ります。上の例のように**計算式で渡す**なら `DATE_FORMAT(NOW(), …)` か `DATE_FORMAT("TODAY", …)` にします（計算式の `"TODAY"` は**現在日時**を返します）。`"NOW"` というトークンは無く、`DATE_FORMAT("NOW", …)` は `Invalid date` になります。

- **式が要ります**（空だと `pKeysFormula`）。対応する `DECLARE` は**配列**で書きます（`pKeysNotArray`）。
- 配列で宣言できるのは `_selected` とこの源泉だけです（ほかは `pArrayOnlySelected`）。
- 配列が**空**のときは実行しません。**空配列の `NOT IN` は全件**になるので、絞りは `IN @keys` 側に書いてください。
- `IN @keys` は読み取りにも書き込み（`UPDATE` / `DELETE` の `WHERE`）にも使えます。
- **数値で宣言した `DECLARE`**（`DECLARE @amount = 0;`）と対になる入力項目は **`type: "number"`**（または選択肢がすべて数で書かれた `"select"`）にします。
  `"text"` / `"date"` / `"datetime"` を当てると `pInputTypeMismatch` で**保存できません**。注入するのは文字列なので、
  文字を当てると**実行時には止まらず、そのまま条件に載る**（`金額 >= "abc"` が 0 件を返す）ためです。
  数値の条件に文字で絞らせたいときは、`DECLARE` を文字列（`= ''`）にして SQL の側で使い方を合わせます。

## 不備で大量に書き換えないための 4 段

**SQL やパラメーターの不備は、そのまま大量の書き換えになります。** `ASSERT` で守れるのは「書いた条件」だけで、
**打ち間違いや空は止まりません**。設定を作るときは、次の 4 段をそろえてください（既定のままでは ① と ③ が抜けます）。

| 段 | 何を防ぐか | 設定 |
|---|---|---|
| ① 入力の必須 | 空のまま実行して、**空の条件で広く当たる**こと | `inputs[].required: true`（**既定は `false`** なので明示する） |
| ② 実行条件 | レコードの項目が空のまま押すこと | `execCond` ＋ `execNgMessage`（押す前に止まり、理由が出る） |
| ③ 書き込み上限 | 桁違いに多いときに、**書く前に止める** | `writeLimit`（**既定は 0 = 無し**。件数の見当を聞いて必ず入れる） |
| ④ 書き込みの確認 | 件数を見てから決める | `confirm: true`（既定） |

- **いちばん効くのは ③ です。** 確認（④）は人が見落としますが、上限は機械が止めます（超える文は書かずに中止）。
  `confirm: false` にするなら `writeLimit` は**必須**です（検査が止めます）が、`confirm: true` でも入れてください。
- `WHERE 請求月 = @m` の `@m` が空なら、**請求月が空のレコードに当たります**。業務データは空の行がまとまりやすいので、
  空を通さない（① ②）のが先です。`ASSERT @m <> '', '…'` でも止められますが、**押す前に止まる ② のほうが親切**です。
- 一覧の一括と `source: "keys"` では、**空配列の `NOT IN` は全件**になります。絞りは `IN @_selected` / `IN @keys` 側に書きます。
- 作った SQL は **`kact_explain`** で見ます。パラメーターが条件に効いていなければ `kintone query: (全件取得)` と出ますし、
  `estimated API consumption` の `read` で読む量の見積もりも分かります。**書き込む文があるアクションは、必ず 1 本ずつ**見てください。
- 利用者に渡すときは、**上限の値とその根拠**（「1 か月の顧客は多くて 200 なので 300 にした」など）を一緒に伝えます。

## 容量

kintone のプラグイン設定の上限は**合計 256 KB**（圧縮して保存）。苦しくなったらアプリを分けて運用します。
