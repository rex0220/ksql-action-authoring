# 反映方法（利用者に必ず伝える）

設定を作った・変えた作業の**最後に必ず**伝えます。AI は kintone に書き込まないので、**反映は利用者の操作だけ**です。

1. kintone のアプリの **［設定］→［プラグイン］→ kSQL アクション →［設定］** を開く。
2. 画面の下の **［設定をアップロード］** で、作った設定ファイル（JSON）を読む。
3. 画面で中身を確かめる（アクションの行・SQL・パラメーター）。**［SQL を検査］** でエンジンの診断も見られる。
4. **［保存する］**（保存のときにプラグインが同じ規則でもう一度検証する）。
5. kintone の **［アプリを更新］（運用環境に反映）**。
6. **ボタンを押して確かめる**（イベント起動なら、レコードを 1 件保存して確かめる）。

## 伝えるときの言葉

- 設定画面の言葉をそのまま使う（**設定をアップロード / 保存する / 運用環境に反映**）。言い換えない。
- **取り込みは設定の全置換**です（アクションを足すだけの取り込み方はありません）。既にアクションがあるアプリでは、
  **先に［設定をダウンロード］で今の設定を取っておき、それに足した形のファイルを作る**ように伝える（`howto-edit`）。
- **既存のレコードは、取り込んだだけでは変わりません。** 値が変わるのは、利用者がボタンを押した・イベントが動いたときだけです。
- 不可逆の注意: アクションは**別アプリにも書き込みます**（UPSERT / DELETE / テーブルの全置換）。
  初めは**確認あり（既定）**・**書き込み上限を小さく**して、試験用のアプリか少ない件数で確かめてから本番の値にする。

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| 保存できない | 画面のエラー。`kact_check` の findings と同じ規則（エラーがあると保存できない） |
| 保存はできたがボタンが出ない | アクションが**有効**か、**起動**（詳細画面は `placements`、一覧画面は `onList` と `panel.views` の区分）、**表示条件**（計算式）、**実行を許す人** |
| 押すと「実行できません」 | 実行条件（計算式）と NG メッセージ |
| 件数が 0 件になる | 論理アプリの対応表のアプリ ID、`WHERE` の項目コード、パラメーターの値 |
