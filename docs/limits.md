# 確認・書き込み上限・安全

## 確認（`confirm`）

| 値 | 実行時 | 用途 |
|---|---|---|
| `true`（既定） | 「<操作> n 件を書き込みます」の確認ダイアログ（`APPLY` があれば子行の数と、戻せない操作である注意も） | 現場の通常のボタン |
| `false` | ダイアログなし。**`writeLimit` が必須** | ワンタッチ・イベント起動 |

断ったときは、その文の書き込みは行われません。

## 書き込み上限（`writeLimit`）

- **起動 1 回で書いてよい合計件数**（一覧は選択全体の累計、グループごとはグループをまたいだ累計）。0 = 上限なし。
- 超えた文は**書かずに止め、起動全体を中止**します。ただし**先行の文が書いた分は残ります**（トランザクションではない）。
- `APPLY` が数えるのは**親の件数**です。子行は `limits.applySubtableMax`（1 文の上限）で見ます。

## 数える単位

| 制限 | 単位 |
|---|---|
| 書き込み上限 | 起動 1 回の累計（一覧は全体。**ループの回をまたいでも累計**） |
| 読み取りの上限件数（`readMax`） | **1 回の読み取りごと**（合計ではない。一時テーブルを作る文の元の読み取りにも効く） |
| 一時テーブルの行数 | `tempTableMax` は出来た表 1 つ、`tempTotalMax` は 1 回の実行で残っている表の合計（一覧の「1 件ずつ」はレコードごと、**ループは回ごと**） |
| 実行タイムアウト | 1 回の実行ごと（**ループは回ごとに計り直す**。切れたら以降は未処理） |
| ループの回数 | `limits.loopMax`（1 つの対象あたり。既定 100）と `limits.runMax`（起動 1 回の合計。既定 1,000） |
| API 通信のタイムアウト | 1 回の通信 |
| 一括の最大件数 | 選んだレコード数（「まとめて 1 回」は min(`listBulkMax`, 200)） |
| `APPLY` の子行 | 1 文（全テーブルの合計。`REMOVE ALL ROWS` で消える既存行も数える） |

## 二重実行

- **同じブラウザー**は止まります（ロックと操作ブロック）。
- **別のユーザー**は、**ログアプリを指定したときだけ**止まります（ログアプリが無ければ重複書き込み・競合が起き得ます）。
  同時に押され得るアクションでは、ログアプリを設定するよう利用者に伝えてください。

## 権限

- 実行はセッション認証で、**押した人の権限を超えません**。
- `allowed`（実行を許す人）は**誤操作防止**で、セキュリティ境界ではありません（本当の防御は kintone の権限設定）。

## ログアプリ（任意）

指定すると、実行の記録（状態・件数・経過・内訳）が残り、`job_key` の重複禁止で別ユーザーの二重実行も止まります。
**記録には業務データの値・SQL 本文・パラメーターの値を書きません**（画面に出るのは `ASSERT` / `EXIT` の文面と、そこに `{@名前}` と書いた変数の値だけ。`sql` の章）。

## 失敗したときに画面に出る文

止まったときは、**何が起きたか・書いた件数・どうすればよいか**を決まった文で出します。
文番号・文の種類・エラーの名前は画面に出しません（ログアプリの「実行詳細ログ」とブラウザーの console に残ります）。

| 原因 | 画面の文（要旨） |
|---|---|
| 読み取りの上限（`readMax`） | 読む件数が上限（N 件）を超えるため、中止しました。／年や月などで分けるか、「読み取りの上限件数」を上げる |
| 一時テーブルの上限（`tempTableMax` / `tempTotalMax`） | 集計の途中で作る表の行数（の合計）が上限を超えるため…／対象を分けるか、上限を上げる |
| kintone の検索の打ち切り | 対象が多すぎて打ち切られたため…／条件で絞り込む |
| 権限（kintone の `CB_NO02`） | アプリかレコードの権限が足りないため…／アプリの管理者に確認 |
| 値の誤り（`CB_VA01`） | 書き込む値を kintone が受け付けませんでした（必須・値の重複禁止・項目の種類など） |
| SQL の誤り（実行時に見つかったもの） | 設定の SQL に誤りがあるため… |
| `ASSERT` | 設定した人の文（`{@名前}` を差し込んだもの） |
| そのほか | 途中で止まりました。／設定する人に、アクションの名前と押した日時を伝える |

どの文にも**書いた件数**（「書き込みはしていません。」か「N 件を書き込んだところで止まりました（書いた分は残っています）。」）が付きます。
業務の言葉で止めたいときは `ASSERT` で先に止めます（`sql` の章「読む前に件数を数えて止める」）。

## ループ（`loop`）を使うとき

- **`writeLimit` が必須**（回ごとの書き込みの確認が出ないので、止める役が上限だけになる）。
- 確認は**実行の前に 1 回だけ**。実行中は進捗と中止（回の境界）。
- **読み取りの上限が「1 回ぶん」の天井に変わる**のが効き目。詳しくは `loop` の章。

## 設定を作るときの安全な既定

1. まず**確認あり**・**`writeLimit` を小さく**して、試験用のアプリか少ない件数で確かめる。
2. `ASSERT` で前提を守る（対象が 0 件、キーが空など）。
3. 全置換（`DELETE` → `INSERT … SELECT`、`REMOVE ALL ROWS` → `APPEND`）は、**`WHERE` の絞りが正しいか**を必ず確かめる
   （絞りを間違えると、関係のない行まで消えます）。
