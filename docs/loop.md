# ループ（同じ SQL を回数ぶん流す。`loop`）

1 本の SQL で大量のデータを扱うとメモリを大量に使うので、**同じ SQL を回数ぶん流して分ける**仕組みです。
分ける軸（年・月・都道府県など）は**利用者が決めて SQL の `WHERE` に書きます**。

| 設定 | 値 | 既定 |
|---|---|---|
| `loop` | **計算式**。空（コメントだけも空と同じ）= ループなし = 1 回 | `""` |
| `loopOnError` | 回が失敗したとき。`"stop"`（停止）/ `"continue"`（続行） | `"stop"` |

## 回数の決め方

| 式が返した値 | 回数 | 回の値（`$val`） |
|---|---|---|
| 空・コメントだけ | 1 回（ループなし。従来どおり） | — |
| 非負の整数 `N` | `N` 回（**`0` は 0 回 = 実行しない**） | `0` … `N-1` |
| 配列（`ARRAY("A", "B")`） | 要素の数（**空配列は 0 回**） | その要素 |
| それ以外（文字列・真偽値・負数・小数・値なし） | **実行前エラー**（1 回も書かない） | — |

- **空の要素と重複は落とします**（SQL に注入した後の文字列で見るので、数値 `1` と文字列 `"1"` は同じ）。
- 式を評価する文脈は**起動の形で決まります**。詳しくは下の表。

## ループ値の渡し方（2 つ）

| 渡し方 | 書き方 |
|---|---|
| **パラメーターの計算式**の `$val` / `$lno` | `params` に `{ name: "year", source: "formula", formula: "2017 + $val" }`。**`$val` は値の型のまま**なので、数の回は足し算になる |
| **予約パラメーター `_loop`** | SQL に `DECLARE @_loop = '';`（`_group` と同じ形。回の値がそのまま入る） |

`$lno` は**0 から数えた回の番号**（空と重複を落とした後の並び）。

**`$val` / `$lno` が使えるのはパラメーターの計算式（`source: "formula"` と `source: "keys"`）だけ**です。
ループの式そのもの・表示条件・実行条件・結果メッセージに書くと、**保存時に「無い項目」の誤り**になります。

試すときは `kact_try` に `loop: { val: 2017, lno: 0 }` を渡します（`$val` / `$lno` が使える文脈になります）。

## 起動の形との組み合わせ

| 起動 | ループ式の評価 | 回数 |
|---|---|---|
| 種類 `app` | **レコード文脈なし**で 1 回 | n（月次・締め処理の**本命**） |
| 詳細画面のボタン | そのレコードで 1 回 | n |
| イベント起動 | そのレコードで 1 回 | n（**保存のたびに n 回流れる**。自己責任） |
| 一覧「1 件ずつ」 | **レコードごと** | Σ（レコードごとの n） |
| 一覧「まとめて 1 回」 | レコード文脈なしで 1 回 | n |
| 一覧「グループごと」 | レコード文脈なしで 1 回（**全グループ同じ回数**） | グループ数 × n |

「1 件ずつ」× ループは **レコードが外側・ループが内側**（レコード 1 の全回 → レコード 2 の全回）。

## 効き目は「読み取りの上限が 1 回ぶんになる」こと

読み取りの上限（`limits.readMax`。既定 10,000・最大 100,000）と一時テーブルの上限、実行の制限時間は
**回ごとに数え直します**。10 回に分ければ、上限を上げずに 10 回ぶん扱えます。
**書き込み上限（`writeLimit`）だけは起動 1 回の累計**のままです。

## 守り

- **ループありは `writeLimit` が必須**（0 だと保存できません）。回ごとの書き込みの確認が出ないぶん、止める役が上限だけになるためです。
- 確認（`confirm: true`）は**実行の前に 1 回だけ**（対象の数・総回数・上限・非トランザクションの注意）。回ごとの確認は自動で承認します。
- `limits.loopMax`（1 つの対象あたりの回数。既定 100）と `limits.runMax`（起動 1 回の合計。既定 1,000）を超えると**実行前に断ります**。
- 実行中は「n / R 回」の進捗と**中止**（回の境界で止まります）。

## 失敗したとき

| 起きたこと | 扱い |
|---|---|
| 回が失敗（SQL エラー・`ASSERT`） | `loopOnError`。**停止** = 残りの回を未処理にしてその対象を失敗に／**続行** = 残りも流してから失敗に。一覧ではさらに `listOnError` に渡す |
| 書き込み上限・制限時間・取消・中止 | `loopOnError` / `listOnError` に依らず**起動全体を止めます** |
| ループ式を展開できない・パラメーターを組めない | **実行の前**に分かります（単発は 1 回も実行しない。一覧ではそのレコード / グループの失敗） |

ログ（任意のログアプリ）には回の内訳が残ります（`loopRuns` / `loopOk` / `loopFailed` / `loopSkipped` / `loopUnprocessed`。
**ループ値そのものは書きません**）。`loopRuns` は**展開した総回数**で、`ok + failed + skipped + unprocessed` と必ず一致します。

結果メッセージでは回の数を `_result_runs` / `_result_ok_runs` / `_result_failed_runs` / `_result_skipped` で使えます
（**ループありのアクションだけ**。既存の `_result_ok` などは**対象（レコード / グループ）の単位のまま**です）。

## 必ず守ること: ループ値を `WHERE` に入れる

**ループは分ける軸を決めるだけで、分ける仕事をするのは SQL の `WHERE` です。**

| 書き忘れ | 何が起きるか | 検査 |
|---|---|---|
| **読み取り**の絞りに無い | 同じ量を回数ぶん読むだけ（効果 0） | 注意 `wLoopReadNoFilter` |
| **書き込み**の絞りに無い | **後の回が前の回の結果を壊す** | 注意 `wLoopWriteNoFilter` |
| ループ値を SQL に渡していない | 同じ SQL をただ繰り返す | 注意 `wLoopNoVariable` |

注意は**保存を止めません**（`kact_check` の warnings に出ます）。出たら書き直してください。
絞りと数えるのは `WHERE` / `HAVING` です（`SET` の値や `SELECT` の列にあるだけでは数えません）。
**ループ値で絞った一時テーブルを元にする文**は、絞られているとみなします。

## 途中で止まったときの原則

ループもトランザクションではありません。**途中の回まで書いた状態で止まり得ます。**

- **起動全体を何度流しても同じ結果になる SQL に限る**（`UPSERT` の標準形。`patterns` の章）。
- **回どうしが重ならない `WHERE`** にする（月・年・都道府県などで分ける）。
- 素の `INSERT` は押し直すたびに増えるので、ループでは使わない。
- **テーブルの全置換（`APPLY … REMOVE ALL ROWS; APPEND … SELECT`）で、回をまたいで同じ親を書かない。**
  全置換なので回ごとに前の回の行が消え、**最後の 1 回ぶんしか残りません**（仕様 §5.7）。
  この形は書き込みがループ値で絞られていないので **注意 `wLoopWriteNoFilter` が出ます**
  （保存は止まりません。出たら必ず書き直してください）。
  回ごとに**違う親**を書く形（`WHERE … = @cust` のようにループ値が親を決める）なら重ならないので使えます。
  明細も分けて流したいなら、明細を**別アプリ**にして `UPSERT` にします（`apply` の章の「ループとは組み合わせない」）。

## 例（年ごとに 10 回に分けて集計し直す）

```json
{
  "code": "agg_10years",
  "name": "10 年分を作り直す",
  "type": "app",
  "placements": [],
  "panelSection": "集計",
  "loop": "10",
  "loopOnError": "stop",
  "confirm": true,
  "writeLimit": 1000,
  "params": [{ "name": "year", "source": "formula", "formula": "2017 + $val" }]
}
```

種類 `app` なので **`placements` は空**で、**`panel` で一覧に出さないとどこにも出ません**（`config` の「パネル・区分」）。

```sql
-- @ksql dialect: 1
DECLARE @year = '';

UPSERT INTO LAPP_集計 (集計キー, 年, 都道府県, 件数, 売上)
SELECT CONCAT(@year, '-', 都道府県) AS 集計キー, @year AS 年, 都道府県,
       COUNT(*) AS 件数, SUM(金額) AS 売上
  FROM LAPP_売上 WHERE 年 = @year      -- ← ここにループ値を入れるのが肝
 GROUP BY 都道府県
ON DUPLICATE (集計キー);
```

月を配列で回すなら `"loop": "ARRAY(\"2026-09\", \"2026-10\", \"2026-11\")"`、パラメーターは `"formula": "$val"` です。

> この例は**元に行があるキーだけ**を書き直します。元の行が無くなったキー（その年の売上を全部消した都道府県など）は
> 集計先に**古い値のまま残ります**。それも 0 にしたいときは、`patterns` の標準形どおり
> **今の集計を「0 の行」として `UNION ALL` で足してから集計**し、集計のあとで `DELETE … AND 件数 = 0` します
> （回ごとの `WHERE 年 = @year` は、足す側の `SELECT … FROM LAPP_集計` にも書きます）。
