# 既存の設定を直す手順

ツールが作るのは**設定全体のファイル**なので、**今の設定を元にしたファイル**を作ります（設定画面の取り込みは 全置換 / 一部置換 / 追加 から選べますが、全置換がこの手順の前提です）。

## 順

1. 今の設定を作業フォルダーに用意する。
   - 利用者に **設定画面の［設定をダウンロード］** で取ってもらい、作業フォルダー（例 `inbox/`）に置いてもらう →
     **`kact_pull`**（`from`）で `settings/APP<アプリ ID>.json` に写す。**元のファイルは残り、写しを直します**。
   - すでに作業フォルダーにあるなら **`kact_files`** で確かめる（`digest` と アクションの数が出る）。
2. **`kact_actions`**（`file`）で中身を見る（1 アクション 1 行）。**返りの `digest` を次で使います。**
   設定ファイルを直接表示しない。
3. **`kact_check`** で今の状態を確かめる（直す前にエラー・注意があるかを知っておく）。
4. **`kact_update_action`** でアクションを 1 つずつ直す。
   - `expectedDigest` に **2 で読んだ `digest`**（読んだ後に変わっていたら `conflict` → `kact_actions` で読み直す）。
   - `action` は**変えるキーだけでよい**（同じコードの行に重ねます）。コードが無ければ**末尾に足します**。
   - コード自体を変えるときは `replaceCode` に古いコードを渡す（**コードはロックキーとログの名前なので、むやみに変えない**）。
   - 書く前に設定全体を検査するので、**エラーがあれば書かずに** `invalid` を返します。
   - 1 回直すと `digest` が変わります。**返った `digest` を次の更新に使う**（または `kact_actions` で読み直す）。
   - 返りの **`changes`** に直したところの差（変わった行だけ）が入るので、**それを利用者に見せる**。
5. **`kact_check`**（SQL を直したなら **`kact_explain`** も）→ `deploy` の反映方法（**全置換**であること）を伝える。

**`kact_diff` を使うのは 2 つのファイルを見比べるとき**です（`kact_pull` で写した元と写し、`kact_save_config` で
別名に書き出した新旧など）。`kact_update_action` は**同じファイルを書き替える**ので、直す前の控えは残りません。
その差は 4 の `changes` で見ます。

共通設定（論理アプリ・制限・ログアプリ）を変えるときは、`kact_save_config` で**別の名前の新しいファイル**として書き出し、`kact_diff` で見比べてください
（`kact_update_action` はアクションだけを直します）。

> **区分の追加と、一覧ごとの出し方は、ツールからは変えられません。**
> `kact_update_action` は `panel` に触れず、`kact_save_config` は**設定全体**を受けるので、
> 今の `panel`（区分の定義・画面 × 区分の表）を知らずに書くと**既定に戻してしまいます**。
> そして `panel` を返すツールはありません。
> そのため、**新しい区分を使いたい・ある一覧でメニューに出したい**という依頼は、
> アクション側（`panelSection` の名前・`onList`・`placements`）までをツールで直し、
> **区分の追加と 画面 × 区分 の表は、利用者に設定画面の［パネル・区分］で直してもらってください**。
> 定義に無い区分を書いたアクションは、保存はできますが**どの一覧にも出ません**（注意 `wUnknownSection`）。
>
> **利用者が設定画面で `panel` を直したら、もう一度［設定をダウンロード］してもらって `kact_pull` し直します。**
> 手元のファイルは直す前の `panel` を持ったままなので、そのまま取り込むと
> **足してもらった区分や、変えてもらった 画面 × 区分 の表が消えます**（取り込みは全置換）。

## よくある直しと、見るところ

| 直したいこと | 変えるところ | 一緒に確かめること |
|---|---|---|
| 詳細画面の出る場所を変える | `placements`（起動） | 種類 `record` だけ（アプリは詳細画面に出せない） |
| 一覧画面の出し方を変える | `onList`（一覧でも使う）と `panelSection`、共通設定の `panel.views` | その区分がその一覧の `sections`（パネル）か `menus`（メニュー）に入っているか |
| 条件でボタンを隠す | `showCond`（表示条件の計算式） | イベント起動には効かない |
| 押せる条件を足す | `execCond` + `execNgMessage` | NG メッセージも計算式 |
| 件数の確認をやめる | `confirm: false` | **書き込み上限が必須**になる |
| 上限を変える | `writeLimit` | 起動 1 回の累計（一覧は選択全体の累計） |
| 対象のアプリを変える | 共通設定の論理アプリの対応表 | SQL の `LAPP_` の名前も合わせる（共通設定は `kact_save_config` で） |
| パラメーターを足す | SQL の `DECLARE` と設定の `params` / `inputs` の**両方** | 名前は大文字小文字を無視して一意。予約名（`_` 始まり）は設定に書けない |
| 選択の渡し方を変える | `selectionMode` | 「まとめて 1 回」「グループごと」では `_record` とレコードの項目を使う計算式が使えない（`selection`） |

## アクションを消すとき

**`kact_delete_action`**（`file`・`expectedDigest`・`code`）。消す前に **`kact_actions` で中身を見せて利用者に確かめる**。
最後の 1 件は消せません（アクションが 0 件の設定は保存できない）。ファイルごと消すかは利用者が決めます。

全置換で取り込む前提なので、**残すつもりのないアクションは消しておく**のが基本です（設定画面で「一部置換」を選んでもらえば、選んだアクションだけを差し替えられます）。
無効（`enabled: false`）にして残すと、**検査されない SQL がプラグイン設定に入ったまま運用に反映されます**。

## 下書きとして置きたいとき

**無効（`enabled: false`）の行は保存時の SQL 検査を通りません**。書きかけの SQL を残したいときは無効にしておく。
`kact_check` も無効の行の SQL は検査しません（`kact_actions` には出ます）。
**下書きのまま運用に反映しない**こと（反映するなら、その前に消すか仕上げる）。
