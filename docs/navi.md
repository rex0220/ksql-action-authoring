# 使い方の案内（できること・頼み方）

**kSQL アクション**（rex0220 kSQL Action）は、アプリ管理者が決めた SQL（kSQL）を、現場の人が**ボタン 1 つ**か**保存のイベント**で実行するプラグインです。
AI（この MCP）は、その**設定ファイル**を作ります。実行するのは利用者の画面です。

## できること（アクションの種類）

| 種類 | 何から動くか | 例 |
|---|---|---|
| レコード | 詳細画面のボタン、保存後／ステータス変更のイベント | 「このレコードの顧客を集計しなおす」「保存したら、その案件の合計を親のアプリに書き戻す」 |
| レコード（一覧でも使う） | 一覧で選んだレコードに対して（同じ行で詳細画面と両方） | 「選んだ受注をまとめて締める」「選んだ明細を 1 つの集計レコードのテーブルに入れる」 |
| アプリ | 一覧のヘッダーメニュー・パネル（レコードに依らない） | 「今月ぶんを全部集計する」「締め処理」 |

できる処理は kSQL の範囲です（別アプリへの追加・更新・削除・UPSERT、テーブルの全置換、一時テーブル、ガード）。
**取得（SELECT）だけを画面に出す道具ではありません**（結果の表示先がないので、トップレベルの SELECT は書けません → `sql`）。

## 任せる範囲を確かめる（作り方の前に）

**SQL で書けるかどうかと、その業務を kSQL アクションに任せてよいかどうかは別**です。頼まれた道具で無理に解かない。
作り方（アプリ・SQL・設定）を考える前に、次の 6 つを確かめる。利用者が「作って」と言っていても、外れる項目があれば先に言う。

| 見ること | 確かめること | 外れる例 |
|---|---|---|
| 任せられる処理か | 突き合わせる**共通のキー**があり、入力の形が決まっている | 振込の名前・名刺・住所のような、表記のゆれた外のデータを突き合わせる |
| 〃 | 答えを決める**決まりを書ける** | 承認・査定、取引先ごとの取り決めや問い合わせで決まる判断 |
| 〃 | 件数が読み取り・書き込みの上限に収まる | 1 回で上限を超える量を毎回読む（`loop` で分けられるかを見る） |
| 任せて安全か | 結果を**元のデータから作り直せる** | 結果が外（会計・督促・取引先への連絡）と結びつき、作り直すと合わなくなる |
| 〃 | 誤りを**書く前に止められる**（`ASSERT`） | 取り違えた結果も形の上では正しく、検査で止められない |
| 〃 | 外へ出る前に**人が確かめる**場がある | その場で正しくないと困る（在庫の引き当て・予約の空き枠。押したとき・保存したときのデータで計算するので、同時に変えた分がずれる） |

**外れる項目があったとき**は、作り方より先に次の 3 つを返し、進めるかを利用者に決めてもらう:

1. どの項目に外れるか、なぜか
2. ほかの方法（その業務のための仕組み・kintone の標準の機能・運用で要らなくする方法）
3. kSQL アクションに任せられる部分（判断は人がして、その後の集計・残高・一覧を kSQL アクションで作る、など）

**話を進めている途中でも見直す。** 次が重なったら、作り方を足す前に、効果・手間・ほかの方法と比べて「採用する価値があるか」を利用者に聞く
（どれもそれ自体は悪くない。見直さないまま続けるのがいけない）:

- 指摘を受けるたびに、案が大きくなる（段・アプリ・決めてもらうことが増える）
- 「ここは人が確かめる」「利用者が合わせる」が増える
- 道具で書けるか（関数があるか）を探し始める
- 別の AI や資料の案を「取り入れる」話になる（取り入れる前に、その案も上の表で見る）

利用者に「無理では」と言われて初めて同意するのは遅い。外れる理由が分かった時点で言う。

## 頼み方の例

- 「受注アプリの詳細画面にボタンを置いて、表示中のレコードの顧客コードで受注を集計して、集計アプリに UPSERT して」
- 「集計アプリの明細を、受注アプリから作り直したい（全置換）」
- 「一覧で選んだ受注を、顧客ごとにまとめて、顧客マスタのテーブルに明細として入れて」
- 「保存したら、その案件の合計金額を親の案件アプリに書き戻して。確認ダイアログは出さず、書き込み上限は 50 件で」
- 「今の設定に、締め済みフラグが立っているレコードではボタンを出さない条件を足して」
- 「10 年分を 1 年ずつ 10 回に分けて集計し直したい」（ループ。1 回ぶんの読み取りが上限に当たるとき）
- 「一覧パネルの区分を横に 4 つ並べて、ボタンの幅を 150 にして」（パネルの見た目。`panel` の `sectionColumns` / `buttonWidth`）

## AI が聞く必要があること（推測しない）

**探す前に聞く。** 一覧を見てから当てにいくと、**選ばせているようで選ばせていない**ことになる
（候補を黙って絞ると、利用者は絞られた後しか見ない）。
利用者が分からないときだけ道具で候補を出し、**どう絞ったかを言って選ばせる**（`howto-new` の「アプリを決める」）。

- **アプリ ID**（論理アプリの対応表に書く。自アプリも名前で書く）。
  **名前でも番号でもよいと聞く**（番号で答えられる人ばかりではない）。
  分からないと言われたら `kact_apps`。**資料の例の番号をそのまま書かない**
- **どの一覧を別扱いにするか**（「この一覧では出さない」など。一覧 ID は `kact_views` で読める。`"*"` の行だけで足りるなら聞かない）
- **実行を許す人**のユーザー・組織・グループのコード
- 項目コード（分からなければ `kact_fields` で読む。ラベルではなくコードを使う）

## 道具の並び

| ツール | すること |
|---|---|
| `kact_docs` | この資料（最初に呼ぶ） |
| `kact_status` | tools の版と、利用者の zip（プラグインの版・オーサリング API・計算式エンジン）の診断 |
| `kact_workspace_status` | 作業フォルダーの場所と、そこにある設定ファイルの名前（下の階層も） |
| `kact_files` | 作業フォルダーの JSON の一覧（設定ファイルは `digest` とアクションの数も） |
| `kact_save_config` | **新しい設定ファイルを保存**（検査を通らなければ書かない。上書きしない） |
| `kact_update_action` | **アクションを 1 つ差し替える・足す**（`digest` で照合。直した差を `changes` で返す） |
| `kact_update_common` | **共通設定を直す**（論理アプリ・時間帯・上限・ログアプリ・**パネルと区分**。`digest` で照合。アクションと共通の文には触らない） |
| `kact_delete_action` | アクションを 1 つ**消す**（`digest` で照合。最後の 1 件は消せない。消す前に利用者に確かめる） |
| `kact_pull` | 今の設定を作業フォルダーに取り込む。**`app`（アプリ番号から直に読む。APIラボ）**か **`from`（ダウンロードしたファイル。元は残す）**。どちらも**出どころ（`source`）**をファイルに残す |
| `kact_check` | 設定ファイルを検査（エラーと注意）。**読み取りで分かる範囲**は本体と同じ規則。`summary.checks` に検査ごとの状態（**`not_checked` = 確かめていない**）、`summary.nextStep` に次にすること。**取り込む直前は `checkSource: true`**（読んだ後に設定画面で直されていないか） |
| `kact_actions` | 設定ファイルの中身を 1 アクション 1 行で見る（SQL 本文は返らない。`digest` 付き） |
| `kact_diff` | 2 つの設定の差（アクション単位。SQL は変わった行だけ） |
| `kact_explain` | アクションの **実行計画**（EXPLAIN）。文ごとの種類と、読むアプリ・条件・使う項目・API の見積もり。控えの項目定義だけを使う（通信なし） |
| `kact_fields` | **kintone の項目定義**（コード・型・ラベル・重複禁止・テーブルの子・**SQL で書ける項目か**）を取って控える。**取った後は計算式を項目コードまで検査する** |
| `kact_apps` | アプリの一覧（**名前で絞れる**。ログイン名とパスワードの接続のときだけ。API トークンでは読めない） |
| `kact_views` | **一覧（ビュー）の ID・名前・種類**。`panel.views` に一覧ごとの行を書くときに使う（「(すべて)」は API に返らないのでツールが足す） |
| `kact_try` | **式の試し計算**（架空の値で評価。値・条件の真偽・SQL に注入される文字列）。kintone には行かない |

書き込むのは**作業フォルダーの中だけ**で、**kintone には何も書きません**（`kact_fields` / `kact_apps` / `kact_views` も読み取り（GET）だけ）。

## kintone の接続（`kact_fields` / `kact_apps` / `kact_views` を使うとき）

利用者が設定した**接続のファイル**（kSQL の `ksql.config.json` と同じ形。kSQL や計算式・印刷屋のオーサリングと**共通で使える**）の
profile だけを使います。**読めているかは `kact_status`** で分かります（ファイルの名前・profile・ホスト・トークンを持つアプリまで。
パスと秘密の値は出ません）。設定が無ければ `kact_fields` / `kact_apps` / `kact_views` は使えませんが、**ほかのツールは使えます**
（そのときは**項目コードと一覧 ID を利用者に確かめる**。計算式の検査は構文だけになる）。
