# 使い方の案内（できること・頼み方）

**kSQL アクション**（rex0220 kSQL Action）は、アプリ管理者が決めた SQL（kSQL）を、現場の人が**ボタン 1 つ**か**保存のイベント**で実行するプラグインです。
AI（この MCP）は、その**設定ファイル**を作ります。実行するのは利用者の画面です。

## できること（アクションの種類）

| 種類 | 何から動くか | 例 |
|---|---|---|
| レコード | 詳細画面のボタン・スペース項目、保存後／ステータス変更のイベント | 「このレコードの顧客を集計しなおす」「保存したら在庫を引き当てる」 |
| 一覧の選択 | 一覧で選んだレコードに対して | 「選んだ受注をまとめて締める」「選んだ明細を 1 つの集計レコードのテーブルに入れる」 |
| アプリ | 一覧のヘッダーメニュー・パネル（レコードに依らない） | 「今月ぶんを全部集計する」「締め処理」 |

できる処理は kSQL の範囲です（別アプリへの追加・更新・削除・UPSERT、テーブルの全置換、一時テーブル、ガード）。
**取得（SELECT）だけを画面に出す道具ではありません**（結果の表示先がないので、トップレベルの SELECT は書けません → `sql`）。

## 頼み方の例

- 「受注アプリの詳細画面にボタンを置いて、表示中のレコードの顧客コードで受注を集計して、集計アプリに UPSERT して」
- 「集計アプリの明細を、受注アプリから作り直したい（全置換）」
- 「一覧で選んだ受注を、顧客ごとにまとめて、顧客マスタのテーブルに明細として入れて」
- 「保存したら、その案件の合計金額を親の案件アプリに書き戻して。確認ダイアログは出さず、書き込み上限は 50 件で」
- 「今の設定に、締め済みフラグが立っているレコードではボタンを出さない条件を足して」

## AI が聞く必要があること（推測しない）

- **アプリ ID**（論理アプリの対応表に書く。自アプリも名前で書く）
- **一覧 ID**（一覧系の起動で「この一覧だけに出す」とき）
- **実行を許す人**のユーザー・組織・グループのコード
- 項目コード（分からなければ `kact_fields` で読む。ラベルではなくコードを使う）

## 道具の並び

| ツール | すること |
|---|---|
| `kact_docs` | この資料（最初に呼ぶ） |
| `kact_status` | tools の版と、利用者の zip（プラグインの版・オーサリング API・計算式エンジン）の診断 |
| `kact_workspace_status` | 作業フォルダーの場所と、そこにある設定ファイルの名前（下の階層も） |
| `kact_files` | 作業フォルダーの JSON の一覧（設定ファイルは `digest` とアクションの数も） |
| `kact_save_config` | **新しい設定ファイルを保存**（検査を通らなければ書かない。上書きしない） |
| `kact_update_action` | **アクションを 1 つ差し替える・足す**（`digest` で照合。直した差を `changes` で返す） |
| `kact_delete_action` | アクションを 1 つ**消す**（`digest` で照合。最後の 1 件は消せない。消す前に利用者に確かめる） |
| `kact_pull` | 設定画面でダウンロードした設定を作業フォルダーに取り込む（元は残す） |
| `kact_check` | 設定ファイルを**プラグイン本体と同じ規則**で検査（エラーと注意） |
| `kact_actions` | 設定ファイルの中身を 1 アクション 1 行で見る（SQL 本文は返らない。`digest` 付き） |
| `kact_diff` | 2 つの設定の差（アクション単位。SQL は変わった行だけ） |

書き込むのは**作業フォルダーの中だけ**で、**kintone には何も書きません**。
